# 产品进化北极星（/goal 粘贴文本）

状态：第 0 轮（观测层）已于 2026-08-13 完成并实机验收。自第 1 轮起按下方五步循环
运行，信号来源与指标记录见 doc/metrics-northstar.md。

## 形态选择

- **主体用 /goal**（长期目标 + 每会话一个增量），不用定时 loop 盲跑：自动迭代的风险不是跑不动，而是没有价值信号时发明需求。
- **定时任务只做信号采集**（只读、不改代码），产出缺陷榜单供 goal 会话消费。
- **workflow 是轮内工具**（如全库审计、多假设验证），不是长期演化的载体。

## 目标声明（每次新会话作为 /goal 整段粘贴）

```
北极星：让每个租户的知识与约束随真实对话自动变准——数据飞轮驱动，不是功能清单驱动。

每轮迭代严格五步：
1. 采信号（只读）：拉取自上轮以来的——转人工会话及原因、知识库检索未命中的
   query、约束命中分布（从不命中 = 疑似死约束；高频命中 = 上游注入失效）、
   各租户 ontology token 量与告警。
2. 排序：按 频次 × 用户伤害 ÷ 修复成本 给缺陷打分，只取第一名；
   方案先写入 doc/active_task.md 再动手。
3. 修复：一个增量，不扩 scope。引擎缺陷改代码；内容缺陷改租户知识/约束，
   并标记"待租户确认"，不代租户拍板事实。
4. 验证：金标回归集全绿（合规/违规文案样本 + 标准问答对）才算完成。
5. 记录并停：把三个北极星指标的本轮变化追加进指标记录。
   涉及 schema 变更 / 跨仓库改动 / 删除数据 / 对外发布 → 停下等人确认。

北极星指标（只认这三个数）：
- 自助解决率 ↑：不转人工且用户未追问纠错的会话占比
- 合规误报率 ↓：被拦内容中人工复核为合法的占比
- 事实过期数 ↓：超过 N 天未复核确认的租户事实条数

反规则：
- 无信号不造需求：本轮信号不足时，只允许补观测能力，不允许发明功能。
- 榜单外不施工：任何"顺手改进"必须先进缺陷榜单参与排序。
- 观测先于优化：第 0 轮先建观测层——金标回归集、约束命中分布统计、
  转人工原因标注。没有信号就没有飞轮。
```

## 为什么是这个方向

1. **数据飞轮是本产品唯一不可抄的护城河。**功能（面板、工作流、渠道接入）竞品都能做；
   "每个租户的约束与知识库被自己的真实会话持续磨准"这件事，随时间复利。
2. **质量来自证据而非规模。**前期调研的两条实证曲线（符号推理的性能悬崖、
   prompt 注入的倒 U 曲线）都指向同一结论：盲目做大做全是负收益，
   按真实信号做小步修正才是正收益区。
3. **三个指标各守一线**：自助解决率守价值（用户得到答案），
   合规误报率守信任（合法内容不被误伤），事实过期数守真实（答案不过期）。
   三者构成互相制衡的目标系，防止单指标被刷。
