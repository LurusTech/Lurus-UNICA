## 五、数据库怎么连

```bash
# UNICA 业务库（产品线、会话、消息、本体……）
wsl docker exec -it unica-dify-postgres psql -U dify -d unica

# Chatwoot 库
wsl docker exec -it unica-chatwoot-postgres psql -U chatwoot -d chatwoot_production
```

业务库口令在 `~/unica-run/admin.env` 的 `DATABASE_URL` 里；
Chatwoot 的在 `deploy/chatwoot-local/.env`（未提交）。

常用查询：

```sql
-- 有哪些客户（产品线）
select name, display_name, dify_agent_id, config_json from product_lines;

-- 某会话的完整问答与置信度
select direction, sender_type, confidence_score, content_json, created_at
from messages where conversation_id = '<id>' order by created_at;

-- 本体校验命中的违规
select kind, property, message, enforced, created_at from claim_violations;

-- 谁是什么角色、属于哪个租户（user_roles/roles 两表已随迁移 017 删除）
select email, role, product_line_id, chatwoot_user_id from users order by role, email;

-- 某次销户到底清了什么（audit 行携带完整清理清单）
select created_at, actor_id, after_state
from audit_logs where resource_type='tenant' and action='delete'
order by created_at desc limit 5;
```

## 七、怎么发一条测试消息

```bash

    "platform_msg_id":"manual-1","platform_meta":{"platform_user_id":"tester"},
    "correlation_id":"manual-1"}}'

# AI 回复从出站流读
wsl docker exec unica-redis redis-cli XREVRANGE unica:outbound + - COUNT 1
```

## 八、启动与停止

```powershell
# 全部拉起（幂等，已在跑的会跳过）
wsl bash /mnt/e/kefu/scripts/start-local-env.sh

# 只看状态
wsl bash /mnt/e/kefu/scripts/start-local-env.sh --status

# 停止
wsl bash /mnt/e/kefu/scripts/start-local-env.sh --stop
```

嵌入服务在 Windows 上，脚本会检测并提示，但**不能替你启动**，需另开一个终端：

```powershell
cd E:\kefu\deploy\embeddings
python server.py
```

**重启电脑后必须做的三件事**：先起 dockerd，再拉起嵌入服务，最后重新查一次 WSL IP。

WSL 没有启用 systemd（`/etc/wsl.conf` 只 boot 了 ssh），所以 **Docker 守护进程
不会自动起**。`docker.sock` 不存在时，上面那个脚本会把四个容器和三个 Go 服务
一起报成"启动失败"，看起来像脚本坏了，其实只是没有 dockerd：

```powershell
wsl -u root bash -lc "service docker start"
```

容器都带 restart 策略，dockerd 一起来它们自己就回来了。

## 九、已知坑

| 坑 | 表现 | 怎么办 |
|---|---|---|
| WSL IP 会变 | 昨天的链接今天打不开 | `wsl hostname -I` 重新查 |
| localhost 不通 | Windows 浏览器连不上 | 用 WSL IP |
| 嵌入服务没起 | 知识库检索全部落空，AI 说"没有这个信息" | 见第八节 |
| ETXTBSY | 换了二进制但行为没变 | 覆盖前先 kill 进程 |
| 消息去重 | 重放测试消息没有任何反应 | 换 `platform_msg_id` |
| 门户曾有死链 | 「客服工作台」「AI 平台」指向已拆的远程机 | 已改为按当前域名推导，跟着 WSL IP 走 |
| 进程名截断 | `pgrep -x router-scene-bin` 查不到活着的进程 | Linux 进程名截断到 15 字符，按端口判断存活 |

| 停用账号 token 未即时失效 | 已停用/已删用户的 access token 在 2 小时 TTL 内仍有效 | 紧急吊销需重启 admin 换 JWT_SECRET；常规等 TTL 过期 |
