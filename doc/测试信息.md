## 一、先看这一条：WSL 地址

```
WSL IP：172.17.158.157
```

**这个 IP 每次重启 WSL 都会变**，用下面这条命令查当前值：

```powershell
wsl hostname -I        # 第一个就是
```

Windows 侧访问 WSL 里的服务**不能用 localhost**（端口转发不通），必须用这个 IP。
反过来，WSL 容器访问 Windows 上的服务用 `172.17.144.1`（WSL 网关，也会变，
用 `wsl bash -lc "ip route | grep default"` 查）。

| Dify api / worker / web / sandbox | `unica-dify-*` | 内部 | |
| Dify Postgres | `unica-dify-postgres` | 5433 | **同时装着 UNICA 业务库 `unica`** |
| Dify Redis | `unica-dify-redis` | 内部 | |
| 业务 Redis | `unica-redis` | 6380 | 消息流 `unica:inbound` / `outbound` / `handoff` |
| 门户 nginx | `unica-portal` | 3401 | 静态文件直接挂 `E:\kefu\portal`，`/api/` 反代到 :8081 |
| Chatwoot rails | `unica-chatwoot-rails` | 3400 | 客服工作台 |

| Chatwoot Postgres | `unica-chatwoot-postgres` | 5434 | 独立库，与业务库无关 |
| Chatwoot Redis | `unica-chatwoot-redis` | 内部 | |

### WSL 里（主机进程，不是容器）

| 服务 | 端口 | 环境文件 | 说明 |
|---|---|---|---|
| admin | 8081 | `~/unica-run/admin.env` | 管理后台 API |
| router | 8090 | `~/unica-run/router.env` | 消息路由，`SCENE_MODE=on` |
| gateway | 8080 | `~/unica-run/gateway.env` | 渠道接入与 Chatwoot 回调 |

> 网关启动后会把出站流里的历史消息排空。演练渠道（`platform='drill'`）
> 没有真实适配器，那些消息会重试三次后进死信队列 `unica:dead-letter`，
> 日志里的 `no adapter registered for channel` 是预期的，不是故障。

二进制都在 `~/unica-run/`。**覆盖运行中的二进制前必须先 kill**，
否则 `cp` 会静默失败（ETXTBSY），旧进程继续跑，看起来像改动没生效。

### Windows 上（不在 WSL）

| 服务 | 端口 | 说明 |
|---|---|---|
| 嵌入模型服务 | 8199 | `deploy/embeddings/server.py`，BGE 中文模型 |

**为什么在 Windows**：模型权重已在 Windows 的 HuggingFace 缓存里，
且 Windows 的 Python 已装好 torch/sentence-transformers。WSL 侧没装 pip。
Dify 容器通过 `172.17.144.1:8199` 访问它。

## 五、数据库怎么连

```bash
# UNICA 业务库（产品线、会话、消息、本体……）
wsl docker exec -it unica-dify-postgres psql -U dify -d unica

# Chatwoot 库
wsl docker exec -it unica-chatwoot-postgres psql -U chatwoot -d chatwoot_production
```

业务库口令在 `~/unica-run/admin.env` 的 `DATABASE_URL` 里；
Chatwoot 的在 `deploy/chatwoot-local/.env`（未提交）。

常用查询：

```sql
-- 有哪些客户（产品线）
select name, display_name, dify_agent_id, config_json from product_lines;

-- 某会话的完整问答与置信度
select direction, sender_type, confidence_score, content_json, created_at
from messages where conversation_id = '<id>' order by created_at;

-- 本体校验命中的违规
select kind, property, message, enforced, created_at from claim_violations;
```

## 七、怎么发一条测试消息

网关跑起来后可以走 HTTP；网关没起时直接往 Redis 流里塞：

```bash
wsl docker exec unica-redis redis-cli XADD unica:inbound '*' payload '{
  "id":"t1","type":"message.inbound","source":"adapter.drill",
  "data":{"channel_id":"3b64b97b-36d2-460e-9660-07910d4a3a3c",
    "content":{"type":"text","text":"民生雅苑多少钱？"},
    "platform_msg_id":"manual-1","platform_meta":{"platform_user_id":"tester"},
    "correlation_id":"manual-1"}}'

# AI 回复从出站流读
wsl docker exec unica-redis redis-cli XREVRANGE unica:outbound + - COUNT 1
```

## 八、启动与停止

```powershell
# 全部拉起（幂等，已在跑的会跳过）
wsl bash /mnt/e/kefu/scripts/start-local-env.sh

# 只看状态
wsl bash /mnt/e/kefu/scripts/start-local-env.sh --status

# 停止
wsl bash /mnt/e/kefu/scripts/start-local-env.sh --stop
```

嵌入服务在 Windows 上，脚本会检测并提示，但**不能替你启动**，需另开一个终端：

```powershell
cd E:\kefu\deploy\embeddings
python server.py
```

**重启电脑后必须做的两件事**：拉起嵌入服务，以及重新查一次 WSL IP。

## 九、已知坑

| 坑 | 表现 | 怎么办 |
|---|---|---|
| WSL IP 会变 | 昨天的链接今天打不开 | `wsl hostname -I` 重新查 |
| localhost 不通 | Windows 浏览器连不上 | 用 WSL IP |
| 嵌入服务没起 | 知识库检索全部落空，AI 说"没有这个信息" | 见第八节 |
| ETXTBSY | 换了二进制但行为没变 | 覆盖前先 kill 进程 |
| 消息去重 | 重放测试消息没有任何反应 | 换 `platform_msg_id` |
| 门户曾有死链 | 「客服工作台」「AI 平台」指向已拆的远程机 | 已改为按当前域名推导，跟着 WSL IP 走 |
| 进程名截断 | `pgrep -x router-scene-bin` 查不到活着的进程 | Linux 进程名截断到 15 字符，按端口判断存活 |
| `pkill -f` 误伤 | 模式会匹配到命令行自身 | 按 PID kill |

## 十、当前遗留问题

详见 `doc/known-defects.md`。与测试关系最直接的：

- **D10**：多轮对话里客户省略主语时（"物业费多少？"），检索会返回**别的记录**
  的数据，模型照单全收。这是当前最挡路的一条。
- **D8**：存量产品线（FreshMart/MegaStore/TechZone/DrillCo*）的知识库仍未接线，
  仍是旧的关键词索引，需逐个回填。
- **D9**：嵌入服务未纳入编排，靠手工启动。
