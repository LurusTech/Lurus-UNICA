# 对话数据脱敏导出说明（给客户的一页纸）

## 为什么要导出

UNICA 回答不了、或按规定必须交给人工的问题，会转给您的坐席。这些转人工记录里
反复出现的问法，能告诉我们本体（您业务的确定性事实表）缺了哪些**客户的说法**。
我们据此整理修改建议，**每一条都要您的人审核通过才会生效**。

我们只从数据里学"客户怎么说"。**事实、价格、比例、承诺，永远不会由系统生成**：
缺了某条事实，系统只会提示"这里缺一条，请您补"，值由您填。

## 导出什么、不导出什么

| 导出 | 不导出 |
|---|---|
| 指定产品线、指定天数内的会话文本（客户、AI、坐席三方消息） | 客户资料表（平台账号、昵称、备注、标签）整表不读 |
| 转人工的原因与当时被拦下的 AI 草稿 | 会话的附加元数据 |
| AI 每次作答的判定记录（原始答复、引用了哪些知识文档、得分） | 客服系统（Chatwoot）里的联系人信息，不在同一个库，不读取 |
| 会话编号（随机生成，不关联任何个人） | 客户编号 |

## 脱敏分三层，都在您的机器上完成

1. **不读**：上表右列的内容，导出语句根本不选。
2. **库内替换**：每个会话的客户昵称，出现在任何文本里都换成〔姓名〕。
3. **规则遮蔽**：手机号、座机、身份证号、银行卡号、邮箱、订单号和各类长单号、
   收货地址、"我叫××/收货人××"一类的姓名、"×先生/女士"、微信号、QQ 号，
   统一替换成〔手机号〕〔地址〕这样的占位符。遮蔽完成后工具会**再扫一遍**：
   只要还能找到一个手机号、证件号、卡号或邮箱，就**一个字节都不写出**，并报错。

政策原文里的数字（"15 天""38000 元""24 小时内""400 热线"）不会被遮蔽，
这些正是比对 AI 答得对不对所需要的。

## 操作步骤（由您的运维执行，我们不登录您的机器）

前提：已升级到含"采集补齐"的版本，并由您在管理后台打开 `evolve_capture`
开关运行过一段时间（例如 30 天）。未打开时库里没有草稿与坐席回复，导出没有意义。

```bash
# 1. 导出（原始文件留在本机）
psql "$POSTGRES_URL" -At -v line='产品线名称' -v days=90 \
     -f unica/scripts/export_redacted.sql > raw.jsonl

# 2. 脱敏 + 残留检查（失败则不产出文件）
evolve redact -in raw.jsonl -out export.jsonl

# 3. 销毁原始文件
shred -u raw.jsonl
```

交付物只有 `export.jsonl` 一个文件。建议您先抽看几行再交付。

## 数据怎么用、存多久

- 只用于为**您这一家**生成本体修改建议和评测报告，不用于其他客户，不用于训练任何模型。
- 我们只把会话编号列表（用于冻结评测集）提交进代码仓库，**对话内容不进仓库**。
- 评测结束后按约定期限删除，默认 90 天。
- 您的库内：会话与判定记录默认保留 180 天，可按您的要求调整。
