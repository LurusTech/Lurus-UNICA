# UNICA 落地形态：从"一套系统"退回"一道闸门"

> 产品不是"AI 客服系统"，而是站在任何客服（AI 或人）和客户之间的一道确定性闸门：用业务自己写下的事实校验每一句回复、把没有依据的承诺扣下、把每次判定留成可校验的证据；并从真实对话里学会该补什么事实，经人审核后发布。

最后更新：2026-10-10。背景与依据见 `doc/competitive-landscape-2026-10.md`。

## 形态阶梯与现状

| 级 | 形态 | 交付物 | 状态（2026-10-09） |
|---|---|---|---|
| L0 | 体检 | `judge checkup`：喂导出对话，本机出 HTML | 已实现，与闸门同一个二进制。支持 UNICA 导出 JSONL、Chatwoot API JSON、带表头 CSV（列名可映射）。脱敏前置，残留即拒写 |
| L1 | 闸门（影子） | `unica/judge serve` + `POST /judge`；Dify 接法、Chatwoot 回调 | 已实现。事实按产品线分文件（`-facts <目录>`，`PUT /facts/{line}`），一家代运营管几十店各自一条链。Dify：HTTP 节点接法 + 插件骨架（骨架未在真实 Dify 打包验证）；Chatwoot：webhook 过闸 + 私信备注。LangBot 中间件未做 |
| L2 | 闸门（执法）+ 自演化 | `-mode enforce`；采集→挖掘→验证门→审核→发布→回滚；证据链；控制台 | 执法开关已实现；自演化闭环与控制台是此前已有的 router/admin 能力，未因本轮改动 |
| L3 | 多租户交付 | 现有八件套 | 未动 |

## 本轮工程改动（计划第 1–4 条）

1. **内核抽出**：`pkg/judge`（纯 Go，只依赖 `pkg/domain`、`pkg/guardrail`、`pkg/marketing`）。`router/internal/guardrail` 的评估器与分诊、`router/internal/marketing` 的标签检测器下沉到 `pkg`。路由器、回放、黄金集、体检、独立二进制全部调用同一个 `judge.Judge`；路由器侧是 Dify 响应到内核输入的薄转换，现有 routing/replay/evolve 测试零改动通过。
2. **独立模块 `unica/judge`**：`gate`（模式、事实存储、证据链）、`server`（HTTP 面）、`chatwoot`（适配器）。无 Postgres：事实 = YAML 文件或内存，证据 = 内存 + 可选 JSONL 追加链，复用 `pkg/compliance` 的哈希链与校验。
3. **体检 CLI**：`unica/judge/internal/checkup` + `judge checkup`。脱敏规则下沉到 `pkg/redact`（导出管道与体检共用一份）；"文本提到哪些属性 / 是否操作类问句"下沉到 `pkg/domain`（挖掘与体检共用）。
4. **行业包升级为内容产品**：`RedlinePack` 增加 `commitments`（承诺类型 → 防火墙线索词）、`cases`（对抗用例，包测试逐条跑，体检单列）、`report`（报告措辞）。电商包为样板。`CheckCommitmentsWithCues` 让包只能让闸门更严，不能替数字背书。

## 影子模式的两条规则

- `would_withhold` 由同一纯函数在"执法孪生配置"下重算，不是估计。
- 任何汇总在样本 < `judge.MinShadowSamples`（30）时只给条数不给比例。闸门与体检共用这一个常量。

## 已决（2026-10-10，owner 授权代决）

1. **开源边界按模块切**：`unica/pkg` 与 `unica/judge` 两个 Go 模块以 Apache-2.0 开放（LICENSE 已放入两模块根），内容为判定内核、本体模型与校验、承诺防火墙、行业包、脱敏规则、证据链哈希、体检 CLI、闸门二进制与接入件。`router`、`admin`、`gateway`、`reporter`、`portal`、`deploy` 保留：自演化闭环（挖掘、验证门、提案、发布回滚）、证据链校验服务与多租户控制台、官方渠道接入。模块边界就是许可边界，不在一个包内切两半。
   - 为此体检从 router 搬进 `unica/judge`，脱敏与属性提及函数下沉到 `pkg`，保证开放模块对保留模块零依赖（`judge/go.mod` 只 require `pkg`）。
   - 公开仓库尚未创建；创建与推送属对外动作，由 owner 执行。
2. **首个行业包 = 电商，首个外部影子对象 = 代运营机构**。工程落点：`-facts` 支持目录模式，一店一个 `<line>.yaml`，`product_line` 选事实、分证据链、分影子汇总；`judge checkup` 可按店各出一份报告。

**不做**（直到第一个外部影子部署出数据）：LangBot 中间件、新的控制台表面、把 `pkg/domain` 拆成开放/保留两半。

## 只看可观测信号

- 时间到首次判定（拿到二进制 → 第一条 `/judge` 返回），目标 10 分钟内。
- 体检报告生成与转发次数（只能靠自述与渠道回流）。
- 外部影子部署数，及每个部署在样本足够后自然产生的"将扣下 N 条"。
- 从影子切到执法的比例——产品自证价值的唯一硬指标。
- 工程侧：抽出后 router 回放测试与演练链路零变化；内核测试不依赖模型与数据库（已满足）。

## 已知边界（不是缺陷，是口径）

- 承诺防火墙只认识带单位的数字与绝对化用语；"退款3个工作日内到账"没有它认识的单位，不会被扣。写进事实仍是对的，只是报告自己看不见。
- Chatwoot 没有发送前钩子，坐席消息只能事后备注，不能拦。
- 单文件 `-facts x.yaml` 只承载默认产品线；`PUT /facts/{其他线}` 返回 409 并提示改用目录。
- 体检的"可自助比例"是上限估算（客户问句命中已写下的事实属性且非操作类请求），报告原文如此标注。
- 证据链文件若在进程崩溃时留下尾部半行，启动时截掉半行继续；中间任何一行坏掉或哈希不符仍拒绝启动。两者的区别是：前者只可能出现在最后一行，后者才是篡改的形状。
- 体检导入里缺时间戳的会话按文件顺序排，不补时间；只有整个会话都有时间才按时间排序。
- 行业包的线索词若同时盖住两个内置绝对词（如一个词里既含"免费"又含"包邮"），只保留先遇到的那个做出处校验；现有包的线索词都没有这种形状。

## 2026-10-10 小模型并行审查

四个维度的只读审查给出 19 条发现，逐条对抗核实后 15 条成立、4 条驳回；按文件分四路修复。成立项里最重的三条：证据链追加失败会留下半行或重复序号、重启后拒绝启动；体检报告里会话 ID 不脱敏；Chatwoot 回调顶层 `message_type` 只按整数解码。驳回的四条都是口径或已有上游限制挡住（请求体 1 MB 上限、离线 CLI 的本地文件、Chatwoot 不重试）。
