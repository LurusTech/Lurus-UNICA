# 跨渠道 AI 客服中枢系统全量综合解决方案 (Full Comprehensive Solution)

## 一、 项目背景与核心目标
本项目旨在打造一套**高可用、私有化部署的全渠道 AI 客服接入与管理平台**。系统将无缝对接微信、抖音、小红书、淘宝、快手五大核心渠道，抹平各平台协议差异。
*   **核心目标：** 初期利用 AI 实现 **2 个核心产品线** 的全天候自动化获客与咨询解答，同时通过完善的路由机制实现人工无缝接管。
*   **创新机制：** 引入 **Persona（人格化身份）** 体系，使不同产品线的 AI 具备独特的性格（如“亲和力强的母婴顾问”或“严谨的技术支持”），提升品牌服务质感。
*   **商业价值：** 确保商业语料、客户画像等核心资产的 100% 私有化，不依赖第三方 SaaS，降低长周期运营成本。

## 二、 核心架构设计思想（三层深度解耦）

### 1. 接入层 (Go/Rust Gateway - “感官与四肢”)
专门负责安全鉴权、协议标准化、全局幂等性过滤及凭证（Token）托管，作为高性能流量前哨。
*   **安全与鉴权：** 执行验签（HMAC/SHA256）、加解密（EncodingAESKey）及频率控制。
*   **Persona 映射：** 网关根据不同渠道或产品 ID，动态挂载对应的 Identity 配置。

### 2. 中枢层 (Chatwoot - “心脏与路由器”)
负责会话生命周期管理与人工协同调度。
*   **统一收件箱：** 聚合各渠道咨询，提供坐席可视化操作界面。
*   **身份视觉化：** 自动将 Persona 设定的 `name` 和 `emoji` 同步至坐席端。
*   **人机握手优先：** AI 默认接待，坐席实时静默旁路监听，支持一键无缝接管并继承 AI 语境。

### 3. 大脑层 (Dify - “智力中心”)
负责逻辑运算、意图识别与 RAG 编排。
*   **人格化驱动：** 将 Persona 中的 `theme` 字段实时注入 LLM 的系统提示词（System Prompt），决定 AI 的语气与行为边界。
*   **多路路由分发：** 识别产品线，通过工作流分发至对应物理隔离的知识库子智能体。

## 三、 人格化配置机制 (Persona & Identity)
系统支持通过标准 JSON 定义 AI 的“服务人格”，实现符合品牌调性的沟通体验：

```json
{
  "id": "product_a_agent",
  "name": "资深育儿顾问",
  "identity": {
    "namer": "雅雅老师",
    "theme": "充满亲和力、耐心且专业的育儿专家，擅长用温暖的语气提供母婴护理建议，说话常用‘亲爱的’、‘您好’开头",
    "emoji": "👩‍🏫"
  }
}
```
*   **核心逻辑：**
    *   **Theme (服务基调)：** 直接决定大模型的语气。例如：亲和型、专家型、极简型。
    *   **Namer (对外昵称)：** AI 自我介绍或在前端显示时的名称，增加真人感。
    *   **Emoji (视觉标识)：** 增强用户感知的品牌符号，使界面更具温度。

## 四、 技术栈与部署规划
*   **开发语言：** Go/Rust (网关层), Ruby (Chatwoot), Python (Dify)。
*   **数据层：** **PostgreSQL (pgvector)** 统一存储向量与关系数据；**Redis** 负责 Token 刷新与防抖。
*   **运维管理工具：**
    *   **Docker Compose：** 针对私有化交付的标准化一键编排。
    *   **Portainer：** 可视化容器管理，支持日志实时查看与服务重启。
    *   **Uptime Kuma：** 7x24 小时状态监控，支持微信/钉钉异常告警。
    *   **Nginx Proxy Manager：** 可视化 SSL 证书管理与反向代理。

## 五、 预期成品效果 (Finished Product Effect)
1.  **全渠道统一：** 一个后台同时处理 5 个平台的私信，操作逻辑高度一致。
2.  **品牌人格化：** AI 不再是生硬的回复机，而是具备品牌温度的“数字员工”。
3.  **极速精准：** RAG 物理隔离确保 A 产品的问题绝不会引用 B 产品的资料，1-3 秒内精准响应。
4.  **业务掌控：** 所有聊天记录私有化存储，支持完整数据审计与画像分析。
5.  **高可靠在线：** 跨供应商双机冗余，Token 自动刷新，业务永不掉线。

## 六、 核心数据流转链路 (The Handshake)
1.  **触达与标准化：** 网关接收平台回调 -> 验签解密 -> 转为内部标准 JSON。
2.  **身份调取：** 调取对应的 Persona 配置文件。
3.  **工单生成：** 网关调用 Chatwoot API 创建消息，坐席端实时可见。
4.  **触发 AI：** Chatwoot 通过 Webhook 将完整会话与 Persona 设定推送至 Dify。
5.  **智能检索与生成：** Dify 依据 `theme` 约束 LLM 风格，结合专属知识库生成回复。
6.  **闭环下发：** Dify 回写 -> 网关调用平台 API 触达终端用户。

## 七、 各平台具体接入操作方法 (全量步骤)

### 1. 微信视频号（小店）
1.  **前期准备：** 微信开放平台完成企业认证；企业微信后台完成注册与认证。
2.  **创建应用：** 企业微信后台创建自建应用，获取 AgentId、Secret；开放平台创建“视频号客服”应用。
3.  **配置回调：** 填写 HTTPS 回调 URL，设置 Token、EncodingAESKey。
4.  **开发模块：** 实现 AES 加解密逻辑；access_token 定时刷新缓存至 Redis。
5.  **对接测试：** 模拟私信，确认意图识别与回复推送闭环。
6.  **上线：** 部署至生产环境，启用监控。

### 2. 抖音商城（抖店）
1.  **账号准备：** 抖音开放平台完成企业认证；注册抖店并确保主体一致。
2.  **应用创建：** 创建“电商服务”应用，获取 app_key、app_secret。
3.  **申请权限：** 勾选“飞鸽客服”、“消息管理”、“订单查询”等权限。
4.  **Token 管理：** 获取并自动刷新 access_token；若需订单数据需获取 shop_access_token。
5.  **回调与幂等：** 设置飞鸽回调 URL；利用 Redis 中的消息 ID 进行幂等性去重。
6.  **适配开发：** 实现接口签名校验、飞鸽消息转换与 AI 回复推送。
7.  **上线运行：** 部署模块并实时监控接口调用状态。

### 3. 小红书商城
1.  **身份认证：** 聚光平台完成品牌方或第三方技术服务商认证。
2.  **获取密钥：** 创建应用，获取 AppKey 和 AppSecret。
3.  **权限申请：** 申请“消息管理”和“商品数据”权限。
4.  **回调配置：** 设置 HTTPS 回调 URL 与密钥；完成店铺后台的应用授权绑定。
5.  **适配开发：** 封装小红书 API，实现消息标准化转换与回复下发。
6.  **联调测试：** 使用测试工具模拟私信与评论消息流转。

### 4. 淘宝商城（千牛）
1.  **平台准备：** 淘宝开放平台完成企业认证，绑定千牛店铺。
2.  **创建应用：** 选择“电商服务-千牛客服对接”场景，获取 AppKey/Secret。
3.  **申请权限：** 申请“千牛客服消息接收/发送”及订单查询权限。
4.  **配置推送：** 开启消息推送功能，填写 HTTPS 回调并设置加密密钥。
5.  **核心开发：** 处理淘宝特定的加密传输协议，实现千牛消息的内部格式转换。
6.  **上线监控：** 确认 AI 回复能正常显示在千牛对话框。

### 5. 快手商城（快手小店）
1.  **前期认证：** 开放平台企业开发者认证；快手小店企业认证。
2.  **应用配置：** 创建“客服机器人”应用，设置授权回调地址。
3.  **权限与授权：** 申请客服消息管理权限；小店后台完成第三方应用授权。
4.  **同步设置：** 开启“客服消息即时同步”与“订单状态即时同步”。
5.  **适配逻辑：** 封装快手 API，实现消息同步接收、格式转换与机器人回复推送。
6.  **正式上线：** 监控授权刷新逻辑，确保 Token 永不过期。

## 八、 极简运维与交付策略
1.  **一键启动：** 交付 `docker-compose.yml` 环境，单命令运行全量 5-8 个容器。
2.  **可视化管理：** 交付 Portainer 界面，客户可直接在网页查看日志、重启容器。
3.  **主动监测：** Uptime Kuma 预置健康检查点，服务异常自动推送至客户微信/钉钉。
4.  **自动备份：** 内置 Cron 脚本，每日凌晨自动 Dump 数据库并保留 7 天记录。

## 九、 服务器建议配置与高可用规划 (初期支撑 2 个产品线)

### 1. 单机建议配置 (共租赁 2 台)
*   **CPU:** 2 核心 / 4 核心；**内存:** 8 GB / 12 GB (建议至少 8G)；**硬盘:** 50 GB - 100 GB SSD；**带宽:** 2 Mbps - 5 Mbps。

### 2. 稳定性保障方案 (供应商隔离)
*   **跨云厂商部署：** 建议分别租赁阿里云与腾讯云服务器，规避单一云平台故障。
*   **高可用模式：** 双机部署网关与 Chatwoot；PostgreSQL 采用主备同步或定期增量同步；两机互相通过 Uptime Kuma 监控。

## 十、 阶段性实施蓝图
1.  **阶段 1 (1-2周)：** 权限筹备与 2 个产品线的人格（Persona）定义。
2.  **阶段 2 (3-4周)：** 基建搭建。租用跨供应商服务器，开发网关 Persona 映射模块。
3.  **阶段 3 (2-3周)：** 中枢集成。部署 Chatwoot/Dify，导入 2 个产品的初始知识库，调试人格化 Prompt。
4.  **阶段 4 (1-2周)：** 全渠道联调。完成抖音、微信等核心渠道的闭环测试。
5.  **阶段 5 (1周)：** 灰度上线。正式服务 2 个产品线，并交付可视化运维手册。
