## 1 系统简介与角色权限

### 1.1 系统能做什么

UNICA 把各平台店铺的客服消息集中起来处理，基本流程如下：

1. 客户在电商或内容平台给店铺发消息。<!-- 依据: README.zh-CN.md:5 -->
2. 系统先由 AI 自动回答。AI 通过 Dify 调用大模型服务，参考本产品线的知识库和"确定性事实"（政策口径）作答。<!-- 依据: README.zh-CN.md:8-15; unica/pkg/difyapp/prompt.go:205-228 -->
3. 遇到不该由 AI 回答、或 AI 没有把握的问题，系统自动转给人工；客户也可以主动要求人工。<!-- 依据: README.zh-CN.md:5; unica/router/internal/handoff/handler.go:206-231 -->
4. 人工客服在「客服工作台」中接待，回复会发回客户所在的平台。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:216-295 -->

### 1.2 系统由哪几部分组成

| 组成部分 | 用途 | 主要使用人 |
|---|---|---|
| 管理门户（页面标题「UNICA 统一管理门户」） | 登录、知识库、渠道、AI 设置、转人工规则、质量复核等全部自助操作 | 运营人员、管理员 |
| 客服工作台（Chatwoot） | 人工接待已转人工的会话 | 客服坐席 |
| AI 应用与知识库（Dify） | 保存提示词与知识库文档，调用大模型服务生成回答 | 一般不直接操作，通过管理门户间接管理 |

<!-- 依据: portal/index.html:160; README.zh-CN.md:8-15,69,149-150; portal/home.html:163-168; portal/admin.html:427-430 -->

### 1.3 产品线与租户

- 在本系统中，一个"产品线"就是一个"租户"。每个租户有自己独立的 AI 应用、知识库、渠道配置和客服工作台账户，互不影响。<!-- 依据: README.zh-CN.md:8-12,25-26; portal/admin.html:357 -->
- 本项目共有 2 个产品线：

| 产品线 | 门户中显示的租户名称 | 工作台中的收件箱名称 |
|---|---|---|
| 产品线一 | 【待填：产品线一名称】 | 「UNICA - 【待填：产品线一的租户名称（name）】」 |
| 产品线二 | 【待填：产品线二名称】 | 「UNICA - 【待填：产品线二的租户名称（name）】」 |

<!-- 依据: 收件箱命名 unica/admin/internal/identity/tenants_onboarding.go:467-469 -->

### 1.4 角色与权限

系统只有两种角色：「管理员」（admin）和「租户用户」（user）。<!-- 依据: unica/admin/internal/rbac/roles.go:1-13 -->

| 能做的事 | 管理员 | 租户用户 |
|---|---|---|
| 登录后首先进入 | 「平台管理」页 | 「我的工作台」页 |
| 可以操作哪些产品线 | 全部（在各功能页上方「租户」下拉框中选择，或从「平台管理」的「进入工作台」进入） | 只有自己所属的一个产品线 |
| 知识库上传与删除、系统提示词、转人工规则、满意度调研、确定性事实、质量复核、修改建议、渠道接入、转人工与 AI 标识、判定证据 | 可以 | 可以（仅本产品线） |
| 免密进入「客服工作台」 | 不可以（管理员没有坐席身份） | 可以 |
| 开户、删除租户、新建与停用账号、平台运维 | 可以 | 不可以 |
| 修复知识库绑定、补建知识库、调整「单次检索召回条数」、更换「生效模型」 | 可以 | 不可以（页面会提示联系管理员） |

<!-- 依据: portal/index.html:178,220; unica/admin/cmd/admin/main.go:483-537; unica/admin/internal/tenant/workbench/workbench.go:40-44; unica/admin/internal/tenant/aisettings/aisettings.go:1251-1252,1342-1343,1547-1548,1603-1604; unica/admin/internal/tenant/aisettings/knowledgeprovision.go:121-122; unica/admin/internal/tenant/aisettings/modeloverride.go:231-232; portal/ai-settings.html:1713-1731 -->

注意：
- 每个账号只能属于一个产品线，且登录邮箱不能重复。同一个人如果要同时处理两个产品线，需要用两个不同的邮箱各开一个账号。<!-- 依据: unica/admin/internal/rbac/roles.go:11-12; unica/router/migrations/006_rbac.sql:14 -->
- 甲方是否持有管理员账号、由谁持有：【待填：管理员账号持有人】。

## 2 登录与账号

### 2.1 登录

1. 用浏览器打开【待填：管理门户访问地址】，页面标题为「UNICA 统一管理门户」。<!-- 依据: portal/index.html:160 -->
2. 看页面下方「系统状态」一栏：「管理服务 (admin)」显示「运行正常」表示可以登录；显示「不可用」请按第 9 章报障。<!-- 依据: portal/index.html:199-205,392-395 -->
3. 在「邮箱」和「密码」中填写账号。<!-- 依据: portal/index.html:181-188 -->
4. 如果是个人专用电脑，可以勾选「记住我（7 天内免登录）」；公共电脑不要勾选。<!-- 依据: portal/index.html:190-193; unica/admin/internal/config/config.go:74 -->
5. 点击「登 录」。<!-- 依据: portal/index.html:195 -->
6. 登录成功后：管理员进入「平台管理」页，租户用户进入「我的工作台」页。<!-- 依据: portal/index.html:178,218-220,245-268 -->

登录失败时页面会显示原因：

| 页面提示 | 含义 | 怎么办 |
|---|---|---|
| invalid credentials | 邮箱或密码不正确 | 核对后重新输入 |
| account is deactivated | 账号已被停用 | 联系管理员启用 |
| 账号未配置有效的角色或所属租户，请联系管理员 | 账号设置不完整 | 联系管理员 |
| 登录失败，请检查网络 | 网络不通 | 检查网络后重试 |

<!-- 依据: unica/admin/internal/handler/auth.go:65-79; portal/auth.js:445-450; portal/index.html:253-260,369-371 -->

注意：前两条提示目前是英文原文，属于系统后台直接返回的文字。<!-- 依据: unica/admin/internal/handler/auth.go:66,71,77; portal/auth.js:446 -->

### 2.2 已保存的账号与切换账号

- 勾选过「记住我」的账号，下次打开门户会出现在「已保存的账号」列表中，点击账号即可进入；点「忘记」可从本机移除该账号。<!-- 依据: portal/index.html:169-174,301-338 -->
- 本机只保存了一个账号时，打开门户会直接进入该账号。<!-- 依据: portal/auth.js:238-251 -->
- 在「我的工作台」右上角点「切换账号」，可回到登录页换另一个账号登录。<!-- 依据: portal/home.html:106; portal/index.html:403-414 -->
- 同时使用两个账号（例如分别管理两个产品线）：每个浏览器标签页各自保持自己的登录。请手动新开一个标签页、粘贴门户地址，再登录另一个账号。在已登录的页面上右键「在新标签页中打开」，新标签页会沿用原来的账号。<!-- 依据: portal/index.html:173; portal/auth.js:7-13 -->

### 2.3 退出登录

点击页面右上角「退出登录」。退出时，该账号也会从本机「已保存的账号」中移除。<!-- 依据: portal/home.html:107,248-253; portal/auth.js:459-465 -->

### 2.4 登录过期

- 使用过程中，系统会在后台自动续期登录，一般不需要重新登录。<!-- 依据: unica/admin/internal/config/config.go:73-74; portal/auth.js:326-372 -->
- 续期失败时，页面会回到登录页（部分页面显示「登录已过期，请重新登录」），重新登录即可。<!-- 依据: portal/home.html:267-270; portal/knowledge.html:1173 -->

### 2.5 账号管理（仅管理员）

**新建账号**

1. 用管理员账号登录，进入「平台管理」页，点击「用户管理」标签。<!-- 依据: portal/admin.html:347-349,384-388 -->
2. 点击「＋ 新建用户」。<!-- 依据: portal/admin.html:395 -->
3. 填写「邮箱」「显示名」「初始密码」；「角色」选「租户用户 (user)」；「所属租户」选择该人员负责的产品线。<!-- 依据: portal/admin.html:754-780 -->
4. 点击「创建」。初始密码系统不会再次显示，请通过安全的方式转交给本人。<!-- 依据: portal/admin.html:766-768,783 -->
5. 列表上方「按租户筛选」可以只看某个产品线的账号。<!-- 依据: portal/admin.html:391-392 -->

**停用与启用账号**

1. 在「用户管理」列表中找到该账号，点击「停用」，状态变为「已停用」。被停用的账号无法登录门户。<!-- 依据: portal/admin.html:3418-3451; unica/admin/internal/handler/auth.go:70-73,140-143 -->
2. 需要恢复时点击「启用」。停用不会删除账号，也不会删除它的操作记录。<!-- 依据: portal/admin.html:3441-3442 -->

注意：停用门户账号后，该人员已经打开的客服工作台（Chatwoot）是否会同时退出登录，【待核实：工作台登录状态是否随门户账号停用而失效】。

**修改或重置密码**

【待核实：当前管理门户没有"修改密码"或"重置密码"的功能，账号修改接口也只支持修改显示名和启用状态。员工忘记密码或需要定期改密时的处理流程，须由实施方确认后补充。】<!-- 依据: unica/admin/internal/identity/users.go:40-43; portal/admin.html:3418-3439 -->

租户用户登录后看到「我的工作台」，顶部显示本产品线名称。页面上的卡片就是全部功能入口：<!-- 依据: portal/home.html:99-115,310-315 -->

### 2.7 「实时运营台」与页面顶栏

在「我的工作台」点「实时运营台」卡片进入（快速跳转里叫「实时事件」）。转人工、被扣下的答复、事实冲突与配置变更，按发生顺序汇在这一页。<!-- 依据: portal/home.html:125-131; portal/live.html:143-144; portal/ui/unica-ui.js:1315 -->

页面分三块：

- 「需要我处理」：紧急与需关注、还没有人处理的事件，标题旁显示数量。你或同事在对应页面处理之后，事件会自动移出；「全部标为已读」只在你当前的浏览器里隐藏，不影响别人。<!-- 依据: portal/live.html:159-165 -->
- 「事件时间线」：每类事件一条泳道，新事件从右侧进入。点开任意一条查看详情，详情里可直接跳到处理该事件的页面。<!-- 依据: portal/live.html:170-176,203-210 -->
- 「当前状态」：本体版本、开关档位与判定留痕的校验结果；点「刷新状态」重新读取。<!-- 依据: portal/live.html:180-196 -->

事件分六类：「强制转人工」「答复已扣下」「可削减的转人工」「事实冲突」「本体变更」「配置变更」；紧急程度分「紧急」「需关注」「通知」三档。<!-- 依据: portal/ui/unica-ui.js:405-454 -->

门户各页面的顶栏有以下功能，设置按浏览器记住：

- 连接状态：「实时」表示事件实时推送；「定时刷新（每 15 秒）」表示实时连接不可用，已改为定时读取；「已断开，正在重连」表示连接中断，会自动重连，无需操作。<!-- 依据: portal/ui/unica-ui.js:1303-1308,1500-1505 -->
- 提示音（「声音：开」/「声音：关」）：默认关闭。开启后，仅强制转人工、答复被扣下、他人发布或回滚本体时发声。<!-- 依据: portal/ui/unica-ui.js:1457-1465 -->
- 浏览器通知（「通知：开」/「通知：关」）：默认关闭。开启后，仅紧急事件、且仅在门户页面不在前台时弹出。如果浏览器拒绝了通知权限，按提示在地址栏左侧的网站设置里重新允许。<!-- 依据: portal/ui/unica-ui.js:1467-1495 -->
- 有待处理事件时，浏览器标签页标题前显示数量，页面图标带角标。<!-- 依据: portal/ui/unica-ui.js:639-648 -->
- 「跳转」：点它或按 Ctrl+K（Mac 上为 ⌘K）打开快速跳转，输入页面名称即可前往；粘贴会话号可直接查看该会话的判定证据（6.9）。<!-- 依据: portal/ui/unica-ui.js:1414-1416,1560-1567,1635-1636,1665 -->

注意：实时推送依赖反向代理的专门配置（见《运维手册》2.6 第 7 步）。如果顶栏一直显示「定时刷新（每 15 秒）」，事件仍会出现，只是最多晚 15 秒；请联系运维检查。

## 3 统一工作台（客服工作台）

### 3.1 先了解几件事

- 客服工作台使用开源客服系统 Chatwoot（v3.15.0），独立部署。它的菜单和按钮不属于本系统程序，本章凡涉及 Chatwoot 自身界面名称的地方都标了【待核实】，交付前须对照现场中文界面逐项核对。<!-- 依据: README.zh-CN.md:87,149 -->
- 工作台里只出现"已经转人工"的会话。AI 自己处理完的会话不会进入工作台。<!-- 依据: unica/router/internal/routing/router.go:433-476; unica/router/internal/handoff/handler.go:72-79 -->
- 两个产品线在工作台中各有独立的账户。转人工的会话进入名为「UNICA - 租户名称」的收件箱。<!-- 依据: README.zh-CN.md:12; unica/admin/internal/identity/tenants_onboarding.go:467-469 -->

### 3.2 进入工作台（免密登录）

1. 用租户用户账号登录管理门户，在「我的工作台」点击「客服工作台」卡片（卡片下方显示「免密进入 →」）。<!-- 依据: portal/home.html:163-168 -->
2. 系统会新开一个浏览器窗口，自动登录工作台，不需要第二个密码。<!-- 依据: portal/home.html:503-526; unica/admin/internal/tenant/workbench/workbench.go:1-8 -->
3. 如果浏览器拦截了新窗口，首页会出现「浏览器拦截了新窗口，请点击链接进入（链接一次性有效）：」，点击后面的「打开客服工作台 →」。链接只能用一次，失效后回到首页重新点击卡片即可。<!-- 依据: portal/home.html:543-559 -->
4. 某个账号第一次进入时，系统会自动为它在工作台中开通坐席身份。<!-- 依据: unica/admin/internal/tenant/workbench/workbench.go:185-229 -->

进入失败时，首页会显示原因：

| 页面提示 | 怎么办 |
|---|---|
| 「该租户尚未接入 Chatwoot 客服工作台，请联系管理员完成开户后再试」 | 联系管理员或实施方 |

### 3.3 转人工会话里有什么

会话转人工后，工作台中会出现一个新会话，内容包括：

1. **一条内部备注**（只有坐席能看到，不会发给客户），依次包含：<!-- 依据: unica/router/internal/handoff/handler.go:159-168,233-287 -->
   - 「【优先接待】」和客户原话：仅当客户自述是老人、未成年人或不会用手机时出现。<!-- 依据: unica/router/internal/handoff/handler.go:242-250; portal/compliance.html:193 -->
   - 「AI 交接摘要」：AI 对本次咨询的概括。
   - 「AI 草稿（确认或修改后可直接发送）」：AI 原本要发出、被系统扣下的答复。不是每次都有。
   - 「转人工原因：…（原因代码，置信度 …）」，以及「说明：」或「违规明细：」补充说明。
2. **之前的聊天记录**：按时间顺序同步进来，每条前面带时间，例如「[14:05:32]」；AI 发过的消息带「[AI]」；系统消息带「[System]」，并作为内部备注显示。<!-- 依据: unica/router/internal/handoff/history_sync.go:101-129 -->
3. **客户资料**：来源平台、渠道、首次出现时间、历史会话数、客户标签。<!-- 依据: unica/router/internal/handoff/handler.go:441-472 -->
4. **转人工之后客户新发的消息**：实时进入同一个会话，前面带渠道来源标记，例如「[WeChat]」；客户发的图片、视频显示为「[Image: 链接]」「[Video: 链接]」。<!-- 依据: unica/router/internal/routing/chatwoot_forwarder.go:84-106,208-225 -->
5. 客户自述需要优先照顾时，会话会被标为紧急。<!-- 依据: unica/router/internal/handoff/handler.go:289-301 -->

常见的「转人工原因」及含义（有中文说明的直接显示中文；没有的显示为原因代码）：

| 备注中显示 | 含义 |
|---|---|
| 置信度不足 | AI 对答案没有把握 |
| 回答与业务事实冲突，已被拦截 | AI 答复与本产品线发布的确定性事实冲突 |
| 命中转人工关键词 | 客户消息里有转人工关键词 |
| 命中敏感话题 | 客户问到了设置的屏蔽话题 |
| AI 服务不可用 | 大模型服务暂时不可用 |
| 答复里的承诺或金额找不到出处，已扣下待人工确认 | AI 答复中的退款、赔偿等承诺或数字找不到资料出处 |
| 意图分诊判定需人工处理 | 平台的意图分诊判断这条消息需要人工 |
| 客户使用快捷入口要求人工 | 客户发了快捷入口（如「人工」） |
| 客户在 AI 答复后重复追问同一问题 | AI 答过后客户又问同一件事 |
| 客户自述需要优先照顾 | 老人、未成年人等 |
| payout_request | 客户要退款金额、赔付结论 |
| liability_payout | 客户问责任归属，需要人工确认后续处理 |
| safety_incident | 食品安全或人身伤害 |
| regulator_threat | 提到监管部门、媒体或批量投诉 |
| funds_at_risk | 资金流向平台外或疑似诈骗 |
| model_requested | AI 自己判断需要人工 |
| empty_answer | AI 没有产出可用的答复，已改为转人工 |

<!-- 依据: unica/router/internal/handoff/handler.go:203-231; unica/pkg/guardrail/evaluator.go:65-111; unica/pkg/judge/judge.go:42-47; portal/evidence.html:285; portal/ui/unica-ui.js:459-477 -->

注意：
- 如果「AI 交接摘要」是一段以 Customer requires human assistance 开头的英文，说明摘要没有生成成功，请直接阅读下面的聊天记录。<!-- 依据: unica/router/internal/handoff/handler.go:303-316 -->
- 同步进来的历史记录最多是该会话最早的 50 条文字消息；超过 50 条时，后面的部分不会同步。图片等非文字内容不在同步范围内。<!-- 依据: unica/router/internal/handoff/handler.go:30-31; unica/router/internal/handoff/history_sync.go:53-73; unica/router/internal/state/repository.go:251-261 -->
- 坐席实际看到的工单是否做到"信息已齐、不必重复询问"，尚未经过真实坐席检验。<!-- 依据: doc/unverified.md:219-223 -->

### 3.4 接待与回复

1. 在工作台会话列表中找到新进来的会话。本系统不会把转人工会话指定给某一位坐席，请坐席在"未分配"的会话列表中主动认领。【待核实：Chatwoot 中"未分配"列表和"分配给我"操作的中文名称；该收件箱是否开启了 Chatwoot 自带的自动分配】<!-- 依据: unica/router/internal/scheduling/distributor.go:60-71; unica/router/internal/scheduling/agent_pool.go:56（坐席上线状态在全部程序中无调用方）; unica/router/internal/handoff/handler.go:135-151 -->
2. 先读内部备注里的摘要和转人工原因，再看上面的聊天记录。客户已经说过的信息不要重复询问。<!-- 依据: unica/pkg/difyapp/prompt.go:228 -->
3. 备注中有「AI 草稿」时，可以复制草稿，核对、修改后作为回复发出。<!-- 依据: unica/router/internal/handoff/handler.go:260-266 -->
4. 在回复框输入内容并发送。公开回复会转发到客户所在的平台。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:216-295 -->
5. 只想给同事看的内容，请以"内部备注（私信备注）"方式发送，内部备注不会发给客户。【待核实：Chatwoot 回复框中切换"回复 / 内部备注"的按钮中文名称】<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:225-229 -->

注意：
- 回复只发出文字。只发图片或文件、不带文字的回复，客户收不到；带文字的，只发出文字部分。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:244-265 -->
- 会话转人工后，AI 不再回复这位客户，直到这个会话结束（见 3.8 节）。<!-- 依据: unica/router/internal/routing/router.go:448-455 -->
- 从转人工那一刻起超过 72 小时，工作台会话与客户之间的对应关系会失效，之后坐席在这个会话里的回复不会送达客户。<!-- 依据: unica/router/internal/handoff/handler.go:28,353-360; unica/gateway/internal/webhook/chatwoot.go:319-321 -->
- 坐席回复送回客户平台的整条链路，尚未在真实 Chatwoot 上验证过。【待核实：上线前须实测"坐席在工作台回复 → 客户在平台上收到"】<!-- 依据: doc/unverified.md:219-223; unica/gateway/internal/webhook/chatwoot.go:267-272; unica/router/internal/handoff/handler.go:332-341 -->

### 3.5 查看完整对话

- **在工作台中**：转人工会话里已同步之前的聊天记录（见 3.3 节）。<!-- 依据: unica/router/internal/handoff/history_sync.go:25-99 -->
- **在管理门户中**：「判定证据」页可以按会话 ID 查看每一轮 AI 判定的执行留痕，包括客户原话、发给客户的答复、被拦下的答复和原因。该功能默认关闭，开启后才开始记录（见 6.9 节）。<!-- 依据: portal/evidence.html:196-211,761,813,820-825; unica/pkg/compliance/ledger.go:46-50 -->
- **会话 ID 在哪里找**：转人工时，系统把会话 ID 写在工作台会话的自定义属性「unica_conversation_id」中。【待核实：该属性在 Chatwoot 界面中的显示位置】<!-- 依据: unica/router/internal/handoff/handler.go:332-341 -->

注意：
- 管理门户中没有"浏览全部历史会话"的页面；AI 独立处理、没有转人工的会话，只能在开启判定留痕之后通过会话 ID 查看。<!-- 依据: portal/home.html:125-194; portal/evidence.html:196-199 -->
- 坐席的回复是否保存在本系统的对话记录中，取决于平台的「本体演化采集」开关：开启时保存；关闭时只保存在工作台中。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:314-336; portal/admin.html:1111-1119; doc/known-defects.md:104-112 -->

### 3.7 对 AI 回复纠错与标注

本系统中，人工对 AI 回复的纠错有三种方式：

| 方式 | 在哪里做 | 作用 |
|---|---|---|
| 当场纠正 | 客服工作台 | 修改「AI 草稿」后再发给客户（3.4 节） |
| 质量复核 | 管理门户「质量复核」页 | 对"AI 回答与确定性事实冲突"的记录做判定 |
| 修改建议 | 管理门户「修改建议」页 | 审核系统从对话中整理出的事实口径修改建议 |

平台开启「本体演化采集」后，坐席的实际回复会被保存，用于之后生成修改建议；数据只保存在本机数据库。<!-- 依据: portal/admin.html:1111-1119; unica/gateway/internal/webhook/chatwoot.go:314-336 -->

#### 3.7.1 质量复核

1. 在首页点击「质量复核」（卡片角标显示「N 条待复核」）。<!-- 依据: portal/home.html:169-175,414-422 -->
2. 页面顶部「状态」默认是「待复核」，也可切换「全部」「本体错了」「模型错了」「误报」；「违规类型」下拉框和「仅拦截」勾选框用于筛选。<!-- 依据: portal/violations.html:214-233 -->
3. 「复核队列」每行显示「发生时间」「违规类型」「属性」「摘要」「模式」「复核状态」。点「展开」查看详情：「AI 回答给出（got）」「本体要求（want）」「证据句」和会话 ID（可点「复制」）。<!-- 依据: portal/violations.html:254-281,966,1001-1014 -->
4. 按判断点击以下按钮之一：
   - 「本体错了」：确定性事实写漏或写错。系统提示「已标记为「本体错了」。请修正本体并重新发布，同类回答才会真正停止。」请到「确定性事实」页修正后重新发布（5.9 节）。违规类型为「承诺或金额无出处」「应由人工核定的数字」「数字无出处」「红线表述（扣下）」「红线表述（仅记录）」的记录不涉及确定性事实，不显示这个按钮。<!-- 依据: portal/violations.html:315-319,392-397,980,1165-1167 -->
   - 「模型错了」：AI 的回答本身有问题。<!-- 依据: portal/violations.html:260-261,981 -->
   - 「误报」：校验规则过严，AI 其实没有答错。<!-- 依据: portal/violations.html:261,982 -->
5. 判断有误时，在已复核的记录上点「重开」，记录回到待复核队列。<!-- 依据: portal/violations.html:977,1170 -->
6. 页面上方「质量概览」显示「自助解决率」「合规误报率」「事实新鲜度」三个参考数字；样本不足时会明确标注「样本不足」。<!-- 依据: portal/violations.html:240-252,845-881 -->

注意：
- 这里记录与"确定性事实"冲突的回答：要有这类记录，须先发布确定性事实，并把「回答校验」设为 shadow 或 enforce（5.9 节）。开启「承诺与金额防火墙」（shadow 或 enforce）后，答复中找不到出处的承诺与数字也记录在这里，违规类型为「承诺或金额无出处」「数字无出处」等。<!-- 依据: portal/violations.html:315-319,921-925 -->
- 知识库内容本身不做对错校验：知识库写错、AI 照着答，这里不会出现记录。<!-- 依据: doc/known-defects.md:369-392 -->
- 确定性事实的校验只在模拟问题集上验证过，尚未经过真实客户消息检验。<!-- 依据: doc/unverified.md:12-17; README.zh-CN.md:134 -->

#### 3.7.2 修改建议

1. 在首页点击「修改建议」（卡片角标显示「N 条待审」）。<!-- 依据: portal/home.html:176-182,423-429 -->
2. 「状态」默认「待复核」；「级别」可选「A 别名」「B 结构化」「C 缺事实」。<!-- 依据: portal/proposals.html:229-248 -->
3. 每条建议显示「差异」「证据对话」「验证门」等信息，帮助判断是否采纳。<!-- 依据: portal/proposals.html:1049-1131 -->
4. 处理方法：
   - A 级、B 级：勾选后点「批量采纳」。采纳会立即发布新版本的确定性事实，可在「确定性事实」页回滚。不合适的点「批量驳回」。<!-- 依据: portal/proposals.html:262-271,1232,1250-1252 -->
   - C 级（缺事实）：点「去补事实」，在「确定性事实」页补上取值并发布，再回到本页点「已补完」；不需要补的点「驳回」。<!-- 依据: portal/proposals.html:1161-1163; portal/ontology.html:845 -->

注意：修改建议由系统在后台从客服对话中整理生成，前提是平台开启「本体演化采集」。【待核实：建议的生成时间与频率】<!-- 依据: portal/proposals.html:262-263,983-985; portal/admin.html:1111-1119 -->

#### 3.7.3 给转人工记录标注真实原因

系统后台已有"给某一次转人工标注真实原因"的功能接口，但管理门户中没有对应的操作页面。【待核实：合同中"人工可对 AI 回复纠错标注"是否需要该页面；如需要，补充页面或调整交付说明】<!-- 依据: unica/admin/internal/tenant/quality/signals.go:311-314; unica/admin/cmd/admin/main.go:527,834-841; portal 目录下各页面无对应入口 -->

### 3.8 结束会话

1. 处理完毕后，在工作台中把会话标记为"已解决"。【待核实：Chatwoot 中该按钮的中文名称】
2. 标记"已解决"后，本系统随即结束这个会话；开启了满意度调研时，同时向客户发出评分邀请。之后客户再发消息，由 AI 重新接待（见 6.7 节）。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:339-389; unica/router/internal/handoff/consumer.go:198-205,222-250; unica/router/internal/state/manager.go:153-196 -->
3. 没有标记"已解决"的会话，静默一段时间后也会自动结束，效果相同。<!-- 依据: unica/router/internal/state/manager.go:347-391; unica/router/internal/routing/router.go:457-476 -->

注意（重要）：
- "已解决"即结束会话，是本版本对一项已确认缺陷的修复，目前只经过程序测试，尚未在真实工作台上验证（附录 C-19）。如果标记"已解决"后，客户新发的消息仍进入工作台，请记下会话 ID，按第 9 章报障；此时会话要等静默满一段时间（默认 30 分钟）才自动结束。<!-- 依据: doc/known-defects.md:71-90; unica/router/cmd/router/main.go:362-366 -->
- 本部署实际的静默时长，可在「设置」页「满意度调研」卡片中的平台设定说明里看到（「平台设定：会话静默 … 后自动结束…」）。<!-- 依据: portal/ai-settings.html:3224-3234 -->
- 人工接待过程中，如果客户和坐席一直在对话、但时间已超过上述静默时长，会话是否会被提前自动结束并回到 AI 接待，【待核实：程序中客户在人工阶段发的消息、坐席第二条及以后的回复，均不刷新会话的活跃时间，需实测】。如发现人工接待中客户的新消息被 AI 回复了，请按第 9 章报障。<!-- 依据: unica/router/internal/state/manager.go:347-352; unica/router/internal/state/repository.go:212-221; unica/gateway/internal/webhook/chatwoot.go:297-308 -->

## 4 知识库管理

知识库用来存放产品介绍、常见问题（FAQ）、话术表、服务说明等资料。AI 回答时会从知识库中查找相关段落作为参考。两个产品线的知识库各自独立。<!-- 依据: README.zh-CN.md:8; unica/admin/internal/tenant/knowledge/knowledge.go:1-7 -->

### 4.1 打开知识库页面

1. 在首页点击「我的知识库」卡片，进入「知识库管理」页。<!-- 依据: portal/home.html:133-139; portal/knowledge.html:134 -->
2. 管理员需先在左上角「租户」下拉框中选择产品线；租户用户只看到本产品线，没有这个下拉框。<!-- 依据: portal/knowledge.html:169-172,471-474 -->
3. 页面中部是文档列表，列出「名称」「状态」「字数」「创建时间」「操作」。<!-- 依据: portal/knowledge.html:190-205 -->

### 4.2 上传文件

1. 点击「上传文件」，在弹出的窗口中选择一个文件（每次一个）。<!-- 依据: portal/knowledge.html:178,181,898-901 -->
2. 文件要求（页面提示原文）：「单个文件不超过 15 MB；支持 txt、markdown、pdf、docx、html、csv、xlsx 等可被解析的文档格式。」<!-- 依据: portal/knowledge.html:183-186; unica/admin/internal/tenant/knowledge/knowledge.go:37-40 -->
3. 上传过程中按钮显示「上传中…」；成功后提示「「文件名」已上传，正在建立索引」，列表顶部出现这篇文档，并显示索引进度。<!-- 依据: portal/knowledge.html:923-929,1003-1011 -->
4. 等状态变为「已完成」，并提示「「文件名」索引完成，已可用于 AI 回答」，这篇文档才开始参与 AI 回答。<!-- 依据: portal/knowledge.html:185,1043 -->

上传被拒绝时的提示：

| 提示 | 原因与处理 |
|---|---|
| 「文件「…」大小为 …，超过 15 MB 上限，请拆分成多个文档后再上传」 | 文件太大，拆分后分别上传 |
| 「文件「…」是空文件，无法上传」 | 文件没有内容 |
| 「上传失败：…」 | 截图后按第 9 章报障 |

<!-- 依据: portal/knowledge.html:909-918,932 -->

### 4.3 粘贴文本

适合把一段 FAQ、一条政策说明直接粘贴进知识库。

1. 点击「粘贴文本」，弹出「粘贴文本」窗口。<!-- 依据: portal/knowledge.html:179,215-218,941-948 -->
2. 「文档名称」：用于在列表中区分文档，页面示例为「退换货政策 2025-08」，最多 200 个字。<!-- 依据: portal/knowledge.html:220-224 -->
3. 「文档内容」：粘贴纯文本内容。页面建议「一篇文档只讲一个主题」。内容上限 15 MB。<!-- 依据: portal/knowledge.html:225-229 -->
4. 点击「提交」。名称和内容都不能为空，否则提示「文档名称和内容都不能为空」。<!-- 依据: portal/knowledge.html:232,957-965 -->
5. 提交后与上传文件相同，等待索引「已完成」。<!-- 依据: portal/knowledge.html:975-979,991-1011 -->

### 4.4 查看索引状态

「状态」一栏可能显示：

| 状态 | 含义 |
|---|---|
| 等待中、解析中、清洗中、分段中、索引中 | 系统正在处理，暂不参与 AI 回答 |
| 已完成 | 已可用于 AI 回答 |
| 索引失败 | 处理失败，请删除后重新上传；仍失败请报障 |
| 已暂停 | 处理已暂停 |
| 已停用（附加标记） | 该文档已被停用 |

<!-- 依据: portal/knowledge.html:270-278,652,1045 -->

注意：页面只自动跟踪索引进度约 2 分钟。超过后会提示「「文件名」仍在索引中，可稍后点击刷新查看」，稍后点「刷新」即可。<!-- 依据: portal/knowledge.html:264-268,1026-1033 -->

### 4.5 查看文档分段

AI 检索时是按"段"取用内容的。可以检查文档被切成了哪些段：

1. 在文档行点击「查看分段」，弹出「文档分段」窗口，顶部显示「共 N 段 · N 字」。<!-- 依据: portal/knowledge.html:238-251,661,808 -->
2. 每段显示字数；被检索命中过的段显示「命中 N 次」。<!-- 依据: portal/knowledge.html:859-861 -->
3. 在「在分段内容中筛选…」框中输入文字可筛选分段；段很多时点「显示更多（还有 N 段）」。<!-- 依据: portal/knowledge.html:244,842 -->
4. 点「关闭」退出。<!-- 依据: portal/knowledge.html:249 -->

### 4.6 搜索、翻页与刷新

- 在「搜索文档」框中输入文档名称的关键字，停止输入片刻或按回车即开始搜索。<!-- 依据: portal/knowledge.html:173-176,728-739 -->
- 每页显示 20 篇，用「上一页」「下一页」翻页。<!-- 依据: portal/knowledge.html:207-211,260 -->
- 点击「刷新」重新读取列表。<!-- 依据: portal/knowledge.html:180,723-726 -->

### 4.7 编辑与更新文档

管理门户中**不能在线修改**已上传文档的内容（只能上传、查看分段、删除）。更新一篇文档的做法是：<!-- 依据: unica/admin/internal/tenant/knowledge/knowledge.go:196-229; portal/knowledge.html:661-662 -->

1. 在本地改好新版本文件（或准备好新版文本）。
2. 按 4.2 或 4.3 节上传新版本，建议在文档名称中写明日期或版本，例如「退换货政策 2025-08」。<!-- 依据: portal/knowledge.html:223 -->
3. 等新版本状态变为「已完成」。
4. 按 4.8 节删除旧版本。先上传新版、再删旧版，可以避免中间出现"知识库里没有这项内容"的空档。

注意：合同中的"可视化编辑"，在当前管理门户中只提供上述"上传、查看分段、删除"的方式。【待核实：知识库文档是否需要提供在线编辑；平台管理中的「Dify 控制台」仅供管理员使用，且页面注明「请勿转交给租户用户」】<!-- 依据: portal/admin.html:427-430 -->

### 4.8 删除文档

1. 在文档行点击「删除」。<!-- 依据: portal/knowledge.html:662 -->
2. 确认提示「确认删除文档「…」吗？该文档及其索引分段会一并移除，此操作不可撤销。」点「确定」。<!-- 依据: portal/knowledge.html:758 -->
3. 成功提示「文档已删除」。删除后该文档不再参与 AI 回答。<!-- 依据: portal/knowledge.html:760-762 -->

### 4.9 分类

知识库没有"分类"栏目，只有文档名称。建议用统一的命名规则区分，例如「类别-主题-日期」，再用「搜索文档」按名称查找。<!-- 依据: portal/knowledge.html:190-200,173-176 -->

### 4.10 更新何时生效

- 新文档在状态变为「已完成」后参与 AI 回答；删除立即移除。<!-- 依据: portal/knowledge.html:185,758,1043 -->
- 如果上传了文档但 AI 始终用不上，先看「设置」页顶部的「接通体检」中「知识库检索」一项（见 5.3 节）。<!-- 依据: portal/ai-settings.html:347-362,2418-2471 -->
- 可用「设置」页的「测试消息」检查 AI 是否引用了新文档（见 5.7 节）。<!-- 依据: portal/ai-settings.html:477-494,3581-3604 -->
- 文档的索引方式由平台统一指定，改动只对此后上传的文档生效，已有文档不会自动重建索引。<!-- 依据: portal/ai-settings.html:757-760 -->

### 4.11 写好知识文档的建议

- **用空行分段，每段讲清一件事。** 系统按"空行"把文档切成段（每段上限约 1000 个词元）。FAQ 建议写成"一问一答为一段，段与段之间空一行"。<!-- 依据: unica/admin/internal/tenant/knowledge/knowledge.go:313-350 -->
- **每段都写出对象名称。** 例如每段都写明是哪款商品、哪项服务。只有第一段写名称、后面各段只写数字，AI 可能把甲的数据安到乙头上。<!-- 依据: unica/admin/internal/tenant/knowledge/knowledge.go:317-332 -->
- **最关键、不能说错的口径（政策、时效、价格、赔付规则）放进「确定性事实」**（5.9 节），不要只放在知识库里。<!-- 依据: doc/known-defects.md:389-392 -->
- 表格类文件（csv、xlsx）由 Dify 解析，其分段方式是否同样按空行切分，【待核实：话术表、FAQ 表格上传后的实际分段效果，建议上线前用「查看分段」逐一检查】。

注意：
- 知识库内容不经过事实校验。知识库中写明"需咨询""以核定为准"的事项，AI 仍可能自己推算出数字；开启「承诺与金额防火墙」后，这类答复会被记录（shadow）或扣下交人工（enforce），见 5.9 节。关键数字仍应写进「确定性事实」。<!-- 依据: doc/known-defects.md:369-424; unica/pkg/domain/commitment.go:66-69,176-189 -->
- 客户追问时常不重复说对象（如"那物业费多少？"），可能导致 AI 取到别的对象的资料。可开启「追问补全对象」缓解（5.8 节）。<!-- 依据: doc/known-defects.md:325-365; portal/ai-settings.html:605-650 -->
- 检索效果与平台的索引方式有关。可在「设置」页「平台运行状态」→「索引方式」查看；若页面提示「两者不一致」「检索会恒空」，请联系管理员。<!-- 依据: portal/ai-settings.html:752-762,2999-3035; doc/known-defects.md:283-321 -->
- 若页面提示「该租户还没有绑定知识库」或「知识库管理当前不可用」，租户用户无法自行修复，请联系管理员或实施方。<!-- 依据: portal/knowledge.html:566-577,600-605; doc/known-defects.md:729-749 -->

## 5 AI 人格与话术配置

### 5.1 两个产品线的 AI 人格

- 每个产品线有自己的 AI 应用和一份「系统提示词」。页面说明：「提示词决定 AI 的身份、语气与作答边界，保存后立即对新会话生效。」两个产品线分别在各自的「设置」页修改，互不影响。<!-- 依据: portal/ai-settings.html:373-383; README.zh-CN.md:8 -->
- 平台默认提示词的第一句是「你是{产品线名称}的在线客服。用简体中文、简洁专业地回答客户问题。」开户时自动填入产品线名称。AI 的身份称呼、语气等"人格"内容，就是在这份提示词里调整。<!-- 依据: unica/pkg/difyapp/prompt.go:200-229 -->

| 产品线 | 人格设定（身份称呼、语气、服务规范） | 确认人 |
|---|---|---|
| 【待填：产品线一名称】 | 【待填：甲方确认的人格设定】 | 【待填】 |
| 【待填：产品线二名称】 | 【待填：甲方确认的人格设定】 | 【待填】 |

### 5.2 「设置」页的布局

在首页点击「设置」卡片进入。管理员需先在「租户」下拉框中选择产品线。页面从上到下分为：<!-- 依据: portal/home.html:154-162; portal/ai-settings.html:330-339 -->

| 区域 | 包含的卡片 | 本手册章节 |
|---|---|---|
| 「接通体检」 | 链路检查 | 5.3 |
| 「回答行为」 | 「系统提示词」「转人工与阈值」「测试消息」 | 5.4–5.7、6.4 |
| 「满意度调研」 | 「满意度调研」 | 5.8 |
| 「知识与检索」 | 「知识库绑定」「追问补全对象」「生效模型」 | 5.8、5.10 |
| 「平台运行状态」（只读） | 「平台开关与索引方式」 | 5.10 |

<!-- 依据: portal/ai-settings.html:346-775 -->

页面右上角「重新加载」可重新读取全部设置。<!-- 依据: portal/ai-settings.html:338 -->

### 5.3 先看「接通体检」

「接通体检」按消息经过的顺序列出各环节是否接通。页面说明：「某一环断了，它下面的设置改了也不会有反应——先看这里，再改设置。」<!-- 依据: portal/ai-settings.html:347-356 -->

- 右上角显示「全部接通」「N 处断开」或「N 项待确认」。<!-- 依据: portal/ai-settings.html:2609-2619 -->
- 检查项包括「上下文变量」「知识库检索」「确定性事实注入」「应答策略注入」「转人工关键词」「生效模型」。<!-- 依据: portal/ai-settings.html:2404-2542 -->
- 断开项旁边的修复按钮（「补齐声明」「补建知识库」「修复检索」）只有管理员能看到；租户用户请联系管理员。<!-- 依据: portal/ai-settings.html:2413,2428-2429,2438,2453 -->

### 5.4 修改系统提示词（AI 人格）

1. 在「系统提示词」卡片的「提示词内容」框中修改文字，例如调整身份称呼、语气、开场方式、需要强调的服务规范。<!-- 依据: portal/ai-settings.html:374-393 -->
2. **不要删除必需内容。** 下方「提示词契约」列出 6 项必需内容，缺少任何一项，保存都会被拒绝，并提示「提示词缺少 N 项必需内容，未保存——见下方契约清单」。这 6 项必须原样保留：<!-- 依据: portal/ai-settings.html:395-403,2001-2008; unica/pkg/difyapp/prompt.go:68-106 -->

   | 必需内容（原样保留） | 名称 | 缺了会怎样 |
   |---|---|---|
   | `{{facts_context}}` | 确定性事实占位符 | 发布的确定性事实不会送进模型 |
   | `{{knowledge_context}}` | 参考知识占位符 | 检索到的知识库内容不会送进模型 |
   | `{{scene_context}}` | 应答策略占位符 | 应答策略恒为空 |
   | `{{experience_context}}` | 历史经验占位符 | 历史经验不会送进模型 |
   | `[FACT:` | 事实引用标签协议 | 断言校验无事可校，质量复核页一直为空 |
   | `[HANDOFF:` | 转人工标签协议 | AI 自己判断该转人工时无法真正转接 |

3. 点击「保存提示词」。系统先读取线上版本做比对：<!-- 依据: portal/ai-settings.html:408,2010-2027 -->
   - 如果打开页面后别人改过，会显示「提示词已被他人修改，未保存」，点「加载线上版本」，确认后再重新编辑。<!-- 依据: portal/ai-settings.html:2063-2085 -->
   - 否则显示改动对比（「删除 N 行，新增 N 行」），确认无误后点「确认覆盖」，不想保存点「取消」。<!-- 依据: portal/ai-settings.html:1930-1980 -->
4. 提示「已保存并生效」表示对新会话立即生效。若提示「已保存，未生效」，表示已存档但没写进 AI 应用，客户收到的仍是上一版；卡片上方会出现「vN 已保存，未生效」提示，点其中的「把 vN 重新推送到 AI 应用」，仍不行请报障。<!-- 依据: portal/ai-settings.html:2044-2052,2145-2152,2181-2227 -->

卡片右上角的状态标签含义：

| 标签 | 含义 |
|---|---|
| 「与平台模板一致」 | 用的是平台默认提示词 |
| 「已自定义」 | 本产品线自己改写过，不会随平台模板更新 |
| 「平台模板有更新」 | 平台模板改过，本产品线仍是旧版 |
| 「控制台之外被改过」 | 有人绕过本页直接修改过；在本页保存一次即可对齐 |
| 「来源未知」 | 早期提示词，无法判断来源 |
| 「契约缺 N 项」 | 线上提示词缺少必需内容，对应功能正在失效 |
| 「未配置 AI 应用」「暂时读不到」 | 无法编辑，请联系管理员或稍后「重新加载」 |

<!-- 依据: portal/ai-settings.html:1685-1786 -->

### 5.5 版本历史与回滚

1. 「系统提示词」卡片下方的「版本历史」列出每次保存、恢复模板、回滚留下的正文版本。<!-- 依据: portal/ai-settings.html:414-428 -->
2. 每行显示「当前版本」标记、来源（「控制台保存」「开户创建」「搬迁自 AI 应用」「平台回推」）、是否「已投影 时间」或「已定版未生效」。<!-- 依据: portal/ai-settings.html:2120-2125,2305-2319 -->
3. 要退回某一版，点该行「回滚到此版」，确认提示后系统提示「已回滚到 vN 并生效」。当前这一版仍留在历史中，可以再回滚回来。<!-- 依据: portal/ai-settings.html:2326,2350-2363 -->

### 5.6 恢复平台模板

- 点「恢复平台模板」，确认「确认恢复平台模板吗？本产线当前的提示词会被覆盖，且无法找回。」后执行。当前正文如果已有版本记录，仍可在版本历史中回滚找回。<!-- 依据: portal/ai-settings.html:409,2095-2109,1936-1941 -->
- 卡片出现「平台模板已更新，本产线仍是旧版」时，可点「更新到最新模板」。这种情况只出现在本产品线此前与平台模板一致、之后平台模板又改过的时候。<!-- 依据: portal/ai-settings.html:1795-1812 -->

### 5.7 用「测试消息」检查效果

1. 在「测试消息」卡片的「测试问题」框输入一句客户可能问的话，例如页面示例「你们的退货时效是多久？」。<!-- 依据: portal/ai-settings.html:477-488 -->
2. 点击「发送」。<!-- 依据: portal/ai-settings.html:490,3528-3542 -->
3. 结果显示 AI 的回答、「置信度 0.xx」，以及「低于当前阈值，线上会转人工」或「高于当前阈值，线上会直接作答」。<!-- 依据: portal/ai-settings.html:3549-3561 -->
4. 下方显示「本次回答可以引用的知识库内容：N 段」及来源文档；或「本次回答没有用到知识库（召回 0 段）」。<!-- 依据: portal/ai-settings.html:3581-3604 -->

测试不会写入任何会话记录。<!-- 依据: portal/ai-settings.html:481-483 -->

### 5.8 话术微调

除系统提示词外，下列文字也直接影响客户看到的话术：

| 话术 | 在哪里改 | 本手册章节 |
|---|---|---|
| 转人工时发给客户的话 | 「设置」→「转人工与阈值」→「转接等待语」 | 6.4 |
| 满意度评分邀请与感谢语 | 「设置」→「满意度调研」 | 本节 |
| AI 回复上的身份标识 | 「转人工与 AI 标识」→「AI 标识与备案公示」 | 6.8 |
| 追问时自动补上对象名称 | 「设置」→「追问补全对象」 | 本节 |

**满意度调研**

会话结束后，系统可以自动给客户发一条评分邀请。默认关闭。<!-- 依据: portal/ai-settings.html:500-512; unica/pkg/survey/config.go:54-56 -->

1. 在「设置」页「满意度调研」卡片中勾选「开启满意度调研」。<!-- 依据: portal/ai-settings.html:514-519 -->
2. 「最少客户消息数」：客户至少发过这么多条消息才发邀请（默认 2）。<!-- 依据: portal/ai-settings.html:521-525; unica/pkg/survey/config.go:57 -->
3. 「等待回复时长（小时）」：超过这个时长未回复，本次调研作废（默认 24）。改动只对此后新发出的调研生效。<!-- 依据: portal/ai-settings.html:527-534; unica/pkg/survey/config.go:58 -->
4. 「调研提问语」：**必须写明回复 1-5 打分**。只有 1 到 5 这五个数字会被认作评分，其他回复会被当成普通消息、重新开启对话。清空可恢复平台文案。<!-- 依据: portal/ai-settings.html:536-543,3281-3284 -->
5. 「评分后的感谢语」：客户打分后收到的回执。清空可恢复平台文案。<!-- 依据: portal/ai-settings.html:546-551 -->
6. 每条文案不超过 500 字。点击「保存」，提示「满意度调研设置已保存」。<!-- 依据: portal/ai-settings.html:556,3183,3285-3288,3314 -->

注意：
- 调研在会话"结束"时发出：坐席在工作台标记"已解决"时，或会话静默满一段时间自动结束时（见 3.8 节）。<!-- 依据: portal/ai-settings.html:3229-3234; unica/router/internal/state/manager.go:153-196 -->
- 超过「等待回复时长」仍未回复的调研，系统会标记为"未回复"并单独计数（本版本新增，尚未实机验证）。这不影响客户收到的内容。<!-- 依据: doc/known-defects.md:39-55; unica/router/internal/survey/timeout.go:119-157; unica/router/internal/routing/router.go:234-242 -->

**追问补全对象**

客户追问时常不再说对象名称（例如先问"某楼盘还有房吗"，再问"物业费多少？"）。开启后，系统会在追问前补上客户上一次提到的对象名称，再去检索和让 AI 回答。<!-- 依据: portal/ai-settings.html:605-619 -->

1. 在「设置」页「追问补全对象」卡片的「追问补全」下拉框中选择：「关闭」「只观察：AI 仍收到原话，只记录本来会补全的次数」「开启：检索和 AI 收到补全后的追问」。页面建议先用「只观察」跑一段时间。<!-- 依据: portal/ai-settings.html:622-630 -->
2. 在「对象名清单」中**每行填一个**客户常问的对象名称（商品、门店、课程等），只填名称，至少 2 个字。<!-- 依据: portal/ai-settings.html:632-639,3418-3425 -->
3. 点击「保存」，提示「追问补全设置已保存」。<!-- 依据: portal/ai-settings.html:646,3450 -->

注意：
- 只补"客户自己说过"的名称；客户一句话里同时提到两个对象时不补。不在清单里的对象无法识别，客户换问别的对象时，可能仍被补成上一个对象，所以请把常问对象都列上。<!-- 依据: portal/ai-settings.html:616-619,635-639 -->
- 若保存后提示「已保存，但运行时缓存未能刷新，正在进行的会话可能要等缓存过期后才生效」，新设置会稍后生效。<!-- 依据: portal/ai-settings.html:3447-3449 -->

### 5.9 确定性事实（政策口径）

「确定性事实」用来声明必须说准的政策、时效、价目、资质。发布后会注入每一次 AI 回答，优先级高于知识库。<!-- 依据: portal/ontology.html:255-260; unica/pkg/difyapp/prompt.go:210-220 -->

内容采用固定格式（YAML）编写，格式要求严格。建议首次由实施方协助编写，甲方运营人员负责日常核对与修改取值。

**编辑与发布**

1. 在首页点击「确定性事实」卡片（角标显示「已发布 vN」或「尚未发布」）。<!-- 依据: portal/home.html:147-153,407-413 -->
2. 在「本体编辑」卡片的「本体 YAML」框中编辑。尚无内容时可点「插入最小模板」，再把所有「〔请填写…〕」换成真实内容。<!-- 依据: portal/ontology.html:255-275,1107-1137 -->
3. 点击「校验」。通过时显示「校验通过」以及渲染预览和字数；不通过时报错会带「第 N 行」，点一下即可跳到对应位置。<!-- 依据: portal/ontology.html:274,287,1172,1193-1233 -->
4. （建议）点击「发布前试跑」：系统根据本体自动生成问题试答，结果列出「问题」「答复」「判定」（「通过」「不通过」「不确定」）「原因」。页面提示「这只能抓到本体表达得出来的错。」<!-- 依据: portal/ontology.html:276,302-319,1285,1314-1324 -->
5. 在「发布备注」中写明改了什么（页面示例「补充退货时效与加急口径」），点击「发布」，确认后提示「已发布 vN」。<!-- 依据: portal/ontology.html:321-327,1239-1261 -->

**回滚**

在「版本历史」中，找到要恢复的版本点「回滚」，确认后提示「已回滚到 vN」。回滚只切换生效版本，不删除任何版本。「发布后质量」一栏显示该版本上线后的参考数据，样本不足时会注明。<!-- 依据: portal/ontology.html:331-353,886-890,934-965,1383-1391 -->

**开关（决定事实是否生效）**

在「开关」卡片中设置，点「保存」后提示「开关已保存」：<!-- 依据: portal/ontology.html:371-474,1530-1532 -->

| 开关 | 选项与含义 |
|---|---|
| 「注入领域事实（inject_facts）」 | 勾选后，发布的事实才会送进 AI 回答。**发布后请确认已勾选。** |
| 「回答校验（validation）」 | 「off — 不校验」；「shadow — 只记录」（照常回答，只记录冲突）；「enforce — 拦截转人工」。未勾选注入时只能是 off |
| 「承诺与金额防火墙（commitment）」 | 「off — 不检查」「shadow — 只记录」「enforce — 扣下交人工确认」：答复中的退款、赔偿等承诺或数字找不到出处时扣下 |
| 「防火墙范围（commitment_scope）」 | 「仅承诺句」或「全部金额」 |
| 「红线包（redline_packs）」 | 选择要扫描的禁用词表 |
| 「高级：熔断参数」 | 拦截比例过高时自动停止拦截的参数，留空用默认值 |

<!-- 依据: portal/ontology.html:381-469 -->

页面对「承诺与金额防火墙」的建议原文：「请先用 shadow 跑一段时间，到「质量复核」页看记录下来的条目判得准不准，再切到 enforce。」回答校验同理，建议先用 shadow 观察。<!-- 依据: portal/ontology.html:398-399,415 -->

注意：
- 新开的产品线，「注入领域事实」和「回答校验」默认都是关闭的。只发布事实而不勾选注入，AI 不会使用这些事实；此时「置信度阈值」不要设到 0.75 及以上，页面在 0.75 档旁提示「事实注入未接通，设到这里会全部转人工」，在 0.80 档旁提示「需先开启事实注入与校验」（见 6.4 节）。<!-- 依据: README.zh-CN.md:23; doc/known-defects.md:466-496; portal/ai-settings.html:2752-2795 -->
- 平台层还有「本体总闸」，关闭时本产品线发布的事实一条都不会注入，可在「设置」页「平台运行状态」查看。<!-- 依据: portal/ai-settings.html:2969-2974 -->
- 事实不要写得过多。事实会随每条消息全部送给 AI，写入过多会淹没真正的政策口径；校验时页面会显示渲染后的字数，可作参考。<!-- 依据: doc/known-defects.md:576-603; portal/ontology.html:1208-1214 -->
- 按区间、阈值分档的政策（例如按延误时长分档补偿），AI 可能跳档。请在该条事实中写明"先算出具体数值再对档"一类的要求，并用「发布前试跑」和「测试消息」检查。<!-- 依据: doc/known-defects.md:428-462 -->
- 校验和熔断参数目前只在模拟问题集上验证过，熔断默认值没有真实流量数据支撑。<!-- 依据: doc/unverified.md:12-17,64-78; README.zh-CN.md:134-136 -->

### 5.10 只有管理员能改的项目，以及只读信息

- 「生效模型」「单次检索召回条数（top_k）」「修复知识库绑定」只对管理员开放，租户用户看到的是说明文字或请联系管理员的提示。<!-- 依据: portal/ai-settings.html:570-600,652-722,1393,1713-1731,3484 -->
- 「平台运行状态」区为只读，显示「意图分诊」「商业阶段策略」「本体总闸」「索引方式」等平台层设定。页面说明：「这些由平台方决定，本页只读；能改的在上面三区。」<!-- 依据: portal/ai-settings.html:730-775,2951-2974 -->

## 6 人机协同流程规范

### 6.1 会话的三种状态

| 状态 | 含义 | 客户新消息由谁处理 |
|---|---|---|
| AI 处理中 | 新会话，或已结束后客户再次来问 | AI 自动回答 |
| 人工处理中 | 已转人工 | 进入客服工作台，由坐席回复；AI 不回复 |
| 已结束 | 静默一段时间后自动结束 | 客户再发消息时重新由 AI 接待；如正在等满意度评分，先当作评分处理 |

<!-- 依据: unica/router/internal/state/machine.go:8-21; unica/router/internal/routing/router.go:433-476 -->

注意：人工处理中的会话不能直接切回"AI 处理中"，只能先结束（见 6.7 节）。<!-- 依据: unica/router/internal/state/machine.go:19 -->

### 6.2 系统自动转人工的情况

| 情况 | 客户收到什么 | 在哪里设置 |
|---|---|---|
| AI 回答的置信度低于「置信度阈值」 | 「转接等待语」 | 「设置」→「转人工与阈值」 |
| 客户消息中包含「转人工关键词」 | 「转接等待语」 | 同上 |
| 客户问到「屏蔽话题」 | 「转接等待语」，AI 不作答 | 同上 |
| AI 答复与确定性事实冲突（回答校验为 enforce） | 「转接等待语」 | 「确定性事实」→「开关」 |
| AI 答复中的承诺或金额找不到出处（防火墙为 enforce） | 「转接等待语」，草稿交坐席确认 | 同上 |
| AI 判断需要人工：客户要金额或赔付结论、问责任归属、食品安全或人身伤害、提到监管部门或媒体、明确要求人工 | AI 的答复照常发出，同时转人工 | 「系统提示词」中的规则（随平台模板提供） |
| 客户报告食用后身体不适或异物、资金流向平台外或疑似诈骗 | AI 答复照常发出，同时转人工 | 系统内置，不可关闭 |
| 平台开启「意图分诊」后，判定需要人工的消息 | 「转接等待语」，不调用 AI | 「平台管理」（管理员） |
| 客户发快捷入口、重复追问、自述需要优先照顾 | 转接提示 | 「转人工与 AI 标识」→「转人工可达」 |
| AI 服务调用失败、AI 没有产出可用答复 | 「转接等待语」，不发出空白答复 | 系统内置 |

<!-- 依据: unica/pkg/guardrail/evaluator.go:185-267; unica/router/internal/routing/router.go:564-587,871-893,1049-1061,1137-1166,1299-1341; unica/pkg/judge/judge.go:42-47,207-249,373-394; unica/pkg/difyapp/prompt.go:227-228; portal/compliance.html:156-158; portal/admin.html:1080-1097 -->

注意：
- 判断"关键词""屏蔽话题"时，只要客户消息**包含**该词就算命中（不区分大小写）。例如关键词「投诉」，客户说"我不是要投诉"也会命中。<!-- 依据: unica/pkg/guardrail/evaluator.go:209-215,252-260 -->
- AI 判断是否需要人工的能力，只在部分产品线的多轮测试中完整验证过。<!-- 依据: doc/unverified.md:200-206 -->

### 6.3 客户如何主动申请人工

客户可以用以下方式要求人工：

1. 发送包含「转人工关键词」的消息。默认关键词为「转人工」「人工客服」「投诉」「找人工」（本产品线可在「设置」中修改）。<!-- 依据: unica/pkg/guardrail/config.go:52; portal/ai-settings.html:451-455 -->
2. 开启「转人工可达」后，客户整条消息**只发**快捷入口（默认「0」或「人工」）即转人工。<!-- 依据: unica/pkg/compliance/access.go:73-77; portal/compliance.html:168-175 -->
3. 客户在对话中明确要求转人工，AI 也会主动转接。<!-- 依据: unica/pkg/difyapp/prompt.go:228 -->

本产品线对客户公布的转人工方式：【待填：例如在欢迎语中写明"回复'人工'转人工客服"】。

注意：平台开启「意图分诊」后，「转人工关键词」整体不再生效，改由分诊判断；此时「设置」页中关键词输入框变灰并显示「平台已启用意图分诊：…」。屏蔽话题与置信度阈值不受影响。<!-- 依据: portal/ai-settings.html:2811-2839; portal/compliance.html:179 -->

### 6.4 配置「转人工与阈值」

1. 进入「设置」页，找到「回答行为」区的「转人工与阈值」卡片。<!-- 依据: portal/ai-settings.html:431-439 -->
2. 「置信度阈值」：取值 0.01～1，越高越容易转人工（默认 0.7）。<!-- 依据: portal/ai-settings.html:441-445; unica/pkg/guardrail/config.go:37 -->
   输入框下方列出三个档位，并标明本产品线能否达到：

   | 档位 | 页面说明 |
   |---|---|
   | ≥ 0.70 | 「检索命中、历史经验、确定性事实，任一即可」 |
   | ≥ 0.75 | 「必须有确定性事实，仅靠历史经验不够」 |
   | ≥ 0.80 | 「必须有事实，且答复的断言经过校验且无冲突」 |

   档位旁显示「本租户可达」才可以放心使用；显示「事实注入未接通，设到这里会全部转人工」或「需先开启事实注入与校验」的档位不要选。<!-- 依据: portal/ai-settings.html:2752-2795 -->
3. 「转人工关键词」：用英文逗号分隔，例如「转人工,人工客服,投诉」。留空则使用平台默认关键词。<!-- 依据: portal/ai-settings.html:451-455 -->
4. 「屏蔽话题（可选）」：用英文逗号分隔。命中时 AI 不作答，直接转人工。<!-- 依据: portal/ai-settings.html:457-461 -->
5. 「转接等待语」：转人工时发给客户的那句话（默认「正在为您转接人工客服，请稍候...」）。不能只填空格。<!-- 依据: portal/ai-settings.html:463-467; unica/pkg/guardrail/config.go:54 -->
6. 点击「保存」，提示「设置已保存，本租户渠道立即生效」。<!-- 依据: portal/ai-settings.html:470,3154 -->
7. 如果提示「…已被他人修改，本次未保存。请点「重新加载」查看当前设置后再改。」，请先点右上角「重新加载」，再重新修改。<!-- 依据: portal/ai-settings.html:3170-3172 -->

### 6.5 配置「转人工可达」

这一组规则在调用 AI 之前判断，命中即转人工，只会增加转人工、不会减少。<!-- 依据: portal/compliance.html:156-158; unica/router/internal/routing/router.go:564-570 -->

1. 在首页点击「转人工与 AI 标识」，找到「转人工可达」卡片。<!-- 依据: portal/home.html:183-188; portal/compliance.html:151-155 -->
2. 「运行方式」三选一：「关闭 — 与未配置时完全相同」（默认）；「观察 — 只记录命中，不转接」；「开启 — 命中即转人工」。页面建议先用「观察」运行一段时间，确认误转少再开启。<!-- 依据: portal/compliance.html:157-167; unica/pkg/compliance/access.go:105 -->
3. 「快捷入口」：整条消息完全等于其中之一才算，用逗号或顿号分隔（默认「0」「人工」）。点「恢复默认快捷入口」可恢复默认。<!-- 依据: portal/compliance.html:168-175; unica/pkg/compliance/access.go:73-77 -->
4. 「重复追问：同一问题第几次提出时转人工」：2～10（默认 2，表示 AI 答复后客户再问一次即转人工）。「比较最近几条客户消息」：2～20（默认 6）。<!-- 依据: portal/compliance.html:181-191; unica/pkg/compliance/access.go:54-64 -->
5. 「优先接待」：勾选后，客户自述"我是老人""年纪大""不会用手机""未成年"或自报不满 18 岁时转人工，工作台会话标为紧急，备注首行注明「【优先接待】」。<!-- 依据: portal/compliance.html:192-194 -->
6. 点击「保存」，提示「已保存」。<!-- 依据: portal/compliance.html:196,577 -->

注意：若提示「已保存，但路由缓存未能刷新：新设置会在缓存过期后生效」，新设置会稍后生效。<!-- 依据: portal/compliance.html:575 -->

### 6.6 人工接管标准流程（SOP）

**上岗前**

1. 登录管理门户，从「客服工作台」卡片免密进入工作台，值班期间保持工作台页面打开（3.2 节）。
2. 值班时段与首次响应时限：【待填：甲方客服服务规范】。

**接待中**

3. 在会话列表中认领新进来的转人工会话（3.4 节第 1 步）。
4. 内部备注首行是「【优先接待】」的会话优先处理，说话放慢、步骤讲清楚。<!-- 依据: unica/router/internal/handoff/handler.go:236-250 -->
5. 读「AI 交接摘要」和「转人工原因」，需要时向上翻看聊天记录。AI 在转人工前已按规则向客户收集关键信息，不要重复询问客户已经说过的内容。<!-- 依据: unica/pkg/difyapp/prompt.go:228; unica/router/internal/handoff/handler.go:233-287 -->
6. 原因为 safety_incident（食品安全、人身伤害）或 funds_at_risk（资金外流、疑似诈骗）的会话，AI 已先给客户发过一条答复，请立即处理，并按甲方应急流程上报：【待填：甲方应急上报流程】。<!-- 依据: unica/pkg/guardrail/evaluator.go:220-250 -->
7. 涉及退款金额、赔付、补偿、退换货是否受理的问题，AI 被设定为不做决定，由坐席按甲方政策答复。<!-- 依据: unica/pkg/difyapp/prompt.go:227 -->
8. 有「AI 草稿」时可以在草稿基础上修改后发送；回复只能发文字（3.4 节）。
9. 需要同事协助时，用内部备注沟通，内部备注不会发给客户。

**发现 AI 答错时**

10. 在回复中向客户更正。
11. 记下会话 ID（3.5 节），会后由运营人员处理：知识库内容有误 → 更新知识库（4.7 节）；政策口径有误 → 修改确定性事实（5.9 节）；对应的冲突记录 → 在「质量复核」中判定（3.7.1 节）。

**结束**

12. 问题处理完毕，告知客户，并在工作台把会话标记为"已解决"（3.8 节）。
13. 记住：标记"已解决"后会话即结束，客户之后的新消息由 AI 接待（6.7 节）；超过 72 小时的会话，回复已无法送达客户（3.4 节）。

### 6.7 交还 AI

- 系统没有单独的"交还 AI"按钮：在工作台标记"已解决"，即结束本系统中的会话；没有标记的会话，静默满一段时间（默认 30 分钟）后自动结束。结束后客户再发消息，由 AI 重新接待。<!-- 依据: unica/router/internal/handoff/consumer.go:222-250; unica/router/cmd/router/main.go:362-366; unica/router/internal/state/manager.go:347-391; unica/router/internal/routing/router.go:457-476 -->
- 开启了满意度调研时，会话结束时向客户发出评分邀请；客户回复 1～5 记为评分，回复其他内容则重新开启对话。<!-- 依据: unica/router/internal/routing/router.go:457-476; portal/ai-settings.html:540-541 -->

注意："已解决"即交还 AI 是本版本的修复，尚未实机验证（3.8 节、附录 C-19）。<!-- 依据: doc/known-defects.md:71-90 -->

### 6.8 AI 身份标识与备案公示

可以在 AI 回复上加一个身份标识，让客户知道是 AI 在回复。<!-- 依据: portal/compliance.html:200-208 -->

1. 在首页点击「转人工与 AI 标识」，找到「AI 标识与备案公示」卡片。
2. 「何时加标识」：「不加」（默认）、「每个会话的第一条 AI 回复」、「每一条 AI 回复」。<!-- 依据: portal/compliance.html:210-217; unica/pkg/compliance/disclosure.go:65-82 -->
3. 「位置」：「回复开头」或「回复末尾（另起一行）」。<!-- 依据: portal/compliance.html:218-224 -->
4. 「标识文字」：最多 30 字，留空使用默认标识「【智能助理回复】」。不能写"仅供参考"一类免责措辞，也不能写"人工客服""真人"一类会让客户以为是人工在回复的说法。<!-- 依据: portal/compliance.html:226-230; unica/pkg/compliance/disclosure.go:18,21-23,109-126 -->
5. 「备案/登记公示」：按实际情况填写所用大模型服务的名称与备案或登记编号，最多 300 字。系统不会代填，也不会把它展示给客户，请另在对外页面或欢迎语中公示。<!-- 依据: portal/compliance.html:231-235 -->
6. 点击「保存」。<!-- 依据: portal/compliance.html:237 -->

标识只加在 AI 回复上，AI 原文一字不改；转人工时的提示语不加标识。对话记录中保存的是带标识的文本。<!-- 依据: portal/compliance.html:206-207 -->

**自查清单**：同页「自查清单」卡片列出各项设置状态（「已设置」「建议处理」「待处理」「未安装」），可点「刷新」更新，点「打印 / 另存 PDF」留档。<!-- 依据: portal/compliance.html:241-257,269-274 -->

本项目备案信息：【待填：备案或登记编号，由甲方提供】。

### 6.9 判定留痕（「判定证据」页）

「判定证据」页记录 AI 每一次"发出、转人工"的判定过程，用于事后查看和执行留痕。<!-- 依据: portal/home.html:189-194; portal/evidence.html:208-211 -->

**开启与关闭**

1. 在首页点击「判定证据」卡片。
2. 页面第一张卡片显示当前状态「已开启」或「未开启」（默认未开启）。点击卡片上的开启或关闭按钮，确认提示后生效。【待核实：该按钮与卡片标题的界面文字含对外禁用表述，交付前需调整界面文字或由甲方确认】<!-- 依据: portal/evidence.html:204-214,531-552; unica/pkg/compliance/ledger.go:46-50 -->
3. 开启后，每次判定都会记录客户原话、决策与原因、所用事实版本、发出或被拦下的答复。关闭后不再记录新的判定，已有记录保留。<!-- 依据: portal/evidence.html:208-211,539-540 -->

**按会话查看**

1. 在「会话 ID」框中填写会话 ID（3.5 节），点击「查看证据」。<!-- 依据: portal/evidence.html:196-199 -->
2. 页面按顺序列出每一轮：决策（「发出」「发出并转人工」「转人工」）、原因、「客户原话」「发给客户的答复」「被拦下、未发给客户的答复」等。<!-- 依据: portal/evidence.html:264-268,758-854 -->
3. 可点「打印 / 另存 PDF」或「导出 JSON」留存。<!-- 依据: portal/evidence.html:243-244 -->

**链头摘要（外部留存）**

1. 点击「下载今日链头摘要」，下载一个文本文件。页面建议每天下载一份，保存在本系统之外。<!-- 依据: portal/evidence.html:220-227 -->
2. 日后需要检查记录是否被改动时，把留存文件中以「unica-answer-audit-head/」开头的那一行粘贴到「比对留存的链头摘要」框，点「比对」。显示「与留存的摘要一致」表示自留存以来记录未被改动。<!-- 依据: portal/evidence.html:229-234,613-630 -->

注意：留痕记录包含客户原话；删除租户时一并删除，按月保留期由运维人员清理。<!-- 依据: portal/evidence.html:211 -->

## 8 常见问题（操作层面）

**问 1：登录时提示 invalid credentials 或 account is deactivated。**
答：前者是邮箱或密码不对；后者是账号已被停用，请联系管理员在「用户管理」中启用（2.1、2.5 节）。<!-- 依据: unica/admin/internal/handler/auth.go:65-79 -->

**问 2：点「客服工作台」后没有打开新窗口。**
答：浏览器拦截了弹窗。首页会出现「打开客服工作台 →」链接，点击即可；链接只能用一次（3.2 节）。<!-- 依据: portal/home.html:543-559 -->

**问 3：进入工作台后看不到任何会话。**
答：工作台只显示已转人工的会话，没有转人工就没有会话。如果确认有转人工但仍看不到，可能是新坐席尚未加入收件箱，请联系本产品线的工作台管理员（3.2 节注意）。<!-- 依据: unica/router/internal/routing/router.go:433-476 -->

**问 4：客户只发了"人工"两个字，没有转人工。**
答：默认关键词是「转人工」「人工客服」「投诉」「找人工」，单独的"人工"不包含这些词，是否转接只能取决于 AI 自己的判断。要让客户单独发"人工"或"0"就一定转人工，需要开启「转人工可达」的快捷入口（6.5 节），或把"人工"加进关键词（6.4 节）。<!-- 依据: unica/pkg/guardrail/config.go:52; unica/pkg/compliance/access.go:73-77 -->

**问 5：上传的文档 AI 一直用不上。**
答：依次检查：① 文档状态是否为「已完成」（4.4 节）；② 「设置」页「接通体检」中「知识库检索」是否接通（5.3 节）；③ 用「测试消息」看是否召回了该文档（5.7 节）。仍不行请报障。<!-- 依据: portal/knowledge.html:185; portal/ai-settings.html:2418-2471,3581-3604 -->

**问 6：文档状态一直是「索引中」。**
答：页面只自动跟踪约 2 分钟，之后请点「刷新」查看。长时间不变请报障（4.4 节）。<!-- 依据: portal/knowledge.html:264-268,1026-1033 -->

**问 7：保存提示词时提示缺少必需内容。**
答：提示词中删掉了 6 项必需内容中的某一项，按「提示词契约」清单补回（5.4 节）。<!-- 依据: portal/ai-settings.html:2001-2008 -->

**问 8：保存后提示「已保存，未生效」。**
答：内容已存档但没写进 AI 应用，客户收到的仍是上一版。点卡片上方提示中的「把 vN 重新推送到 AI 应用」，仍不行请报障（5.4 节）。<!-- 依据: portal/ai-settings.html:2145-2152,2178-2227 -->

**问 9：「转人工关键词」输入框是灰色的，改不了。**
答：平台开启了意图分诊，关键词表整体不再生效（6.3 节）。<!-- 依据: portal/ai-settings.html:2811-2839 -->

**问 10：客户发了图片，AI 没有任何回复。**
答：AI 只处理文字消息，客户只发图片时 AI 不回复，也不会自动转人工。转人工之后，客户发的图片会以链接形式出现在工作台中。<!-- 依据: unica/router/internal/routing/router.go:556-562; unica/router/internal/routing/chatwoot_forwarder.go:84-100 -->

**问 11：客户看到回复中有 [FACT:…]、【HANDOFF:…】一类奇怪的标记。**
答：这是系统内部标记，正常情况下会被去掉。旧版本在 AI 写成全角符号时可能漏出，本版本已能识别全角写法（尚未实机验证）。如果仍看到，尤其是漏出【HANDOFF:…】时（这次转人工可能也没有发生），请记下会话 ID 立即报障，并由人工跟进该客户。<!-- 依据: doc/known-defects.md:697-705; unica/pkg/domain/tags.go:35-40,119-158 -->

**问 12：坐席在工作台点了"已解决"，客户再发消息还是进了工作台。**
答：本版本中，标记"已解决"会立即结束本系统中的会话（3.8 节）。如果仍出现这种情况，可能是该修复在现场未生效，请记下会话 ID 按第 9 章报障；会话会在静默一段时间后自动结束。<!-- 依据: doc/known-defects.md:71-90 -->

**问 13：坐席回复了，客户说没收到。**
答：请检查：① 回复是否只有图片或文件（只能发文字）；② 是否误用了内部备注；③ 是否已超过转人工后 72 小时。都不是请记下会话 ID 报障（3.4 节）。<!-- 依据: unica/gateway/internal/webhook/chatwoot.go:225-247,319-321 -->

**问 14：满意度调研发出后，客户回复的是文字而不是分数。**
答：只有 1～5 的数字算评分，其他内容会被当作新消息，由 AI 重新接待（5.8 节）。<!-- 依据: portal/ai-settings.html:540-541 -->

**问 15：改了设置多久生效？**
答：「转人工与阈值」保存后立即生效；系统提示词保存后对新会话立即生效；确定性事实发布后生效；部分设置保存时若提示"缓存未能刷新"，会稍后生效。<!-- 依据: portal/ai-settings.html:380,3154; portal/ontology.html:1246-1247; portal/compliance.html:575; portal/ai-settings.html:3447-3449 -->

**问 16：个别客户消息没有得到任何回复。**
答：极少数情况下（例如系统在处理过程中重启），重复投递的消息会被当作重复而跳过。请记下客户和时间报障，由人工跟进。<!-- 依据: doc/unverified.md:176-178 -->

**问 17：一个人要同时管理两个产品线。**
答：每个账号只属于一个产品线，需要两个不同邮箱的账号，分别在两个浏览器标签页中登录（1.4、2.2 节）。<!-- 依据: unica/admin/internal/rbac/roles.go:11-12; portal/index.html:173 -->

**问 18：忘记密码怎么办？**
答：管理门户目前没有找回或修改密码的功能，请联系管理员或实施方处理（2.5 节）。【待核实：处理流程】<!-- 依据: unica/admin/internal/identity/users.go:40-43 -->

| 索引 | 文档上传后系统建立检索的过程；「已完成」后才参与回答 |
| 置信度 / 置信度阈值 | AI 对答案把握程度的分数；低于阈值即转人工 |
| 转接等待语 | 转人工时系统发给客户的那句话 |
| 内部备注 | 工作台中只有坐席可见、不发给客户的消息 |
| AI 草稿 | AI 原本要发出、被系统扣下交给坐席的答复 |
| shadow（观察 / 只记录） | 只记录、不改变实际行为的试运行方式 |
| enforce（拦截） | 真正拦截并转人工的运行方式 |
| 熔断 | 拦截比例过高时自动停止拦截的保护机制 |
| 意图分诊 | 平台层在调用 AI 之前判断消息是否需要人工的功能 |
| 追问补全对象 | 客户追问未说对象时，自动补上上一次提到的对象名称 |
| 判定留痕 / 链头摘要 | 「判定证据」页对每次判定的记录，以及用于日后核对记录是否被改动的摘要 |
| 会话 ID | 本系统中一次会话的编号，用于查询和报障 |
| Webhook 地址 | 平台把客户消息推送给本系统的接收地址 |
