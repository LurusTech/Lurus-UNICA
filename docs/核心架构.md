核心架构思想拆解：

1. 边界绝对清晰：“各司其职”的彻底解耦
系统被严格划分为三个互不干涉的域，每个组件只做自己最擅长的事，避免“单体应用”的臃肿：


接入层（Go/Rust 网关）= “感官与四肢”： 专门干脏活累活。负责在最前线扛住高并发，处理微信、抖音、小红书等渠道复杂的鉴权、验签、加密和限流 。它没有任何业务逻辑，只负责“搬运和翻译”。


中枢层（Chatwoot）= “心脏与路由器”： 负责整个客服系统的生命周期管理。维护会话状态、分配工单、提供人工坐席的可视化操作界面 。它是数据流转的十字路口。


大脑层（Dify）= “智力中心”： 专职处理 NLP 与逻辑运算。负责意图识别、检索知识库，并调用大模型生成回复 。

2. 协议抹平：“一次开发，多渠道复用”
这是解决五大平台 API 极度混乱的核心思想。
无论外部是微信的 XML、抖音的带签名 JSON，还是小红书的回调格式，只要经过 Go/Rust 网关，必须被强制“清洗”并转换为系统内部统一的标准 JSON 格式 。
这意味着，你的核心层（Chatwoot 和 Dify）永远只需要认识一种数据结构。未来如果要新增京东或拼多多渠道，核心层代码一行都不用改，只需在网关层新增一个“翻译插件”即可 。

3. 物理隔离与逻辑统一：支撑多产品矩阵
公司旗下有 Ailurus 等 7-8 个独立的产品线，架构上必须做到“统一接客，分库思考”：


逻辑统一： 无论客户咨询哪个产品，都从统一的网关进入，由统一的人工客服团队在 Chatwoot 工作台上接待，实现管理上的聚合 。


物理隔离： 在 Dify 和 PostgreSQL (pgvector) 层面，这 7-8 个产品的知识库、销售话术、PDF 说明书必须被切分为独立的向量表 。通过 Dify 的路由机制，确保询问 Ailurus 的问题，绝对不会检索到其他产品的资料，从根源上消除 AI 的“串档幻觉”。

4. 兜底至上：无缝的“人机握手”优先
AI 是用来降本增效的，但不能以牺牲客户体验为代价。架构设计必须将“人机协同”视为一等公民 ：

所有会话默认先由 AI 接待，但 Chatwoot 的人工界面会实时静默旁路监听 。

一旦 Dify 识别出意图置信度过低、遇到复杂售后，或者用户触发“人工”关键词，系统必须能瞬间阻断 AI 发言，将会话控制权平滑移交给 Chatwoot 的人工坐席，且人工接管时能看到之前的完整 AI 对话上下文 。

5. 数据资产私有化与高可用底座

绝对掌控： 所有聊天记录、客户画像、Prompt 提示词、产品核心语料，全部沉淀在你私有部署的 PostgreSQL 集群中，不依赖任何第三方 SaaS 平台，确保商业机密与数据合规 。


高可用弹性： 利用 K3s 的容器化编排，将无状态的 Go/Rust 网关根据流量波峰波谷动态扩缩容，通过 Redis 缓解数据库读写压力并处理网关的接口防抖 。
